# Deploy on the Ableton PC (S5, `docs/superpowers/specs/2026-09-28-s5-deploy-design.md`)

- **Only a hosted-CI build of `master` is installed.** The `bundle` job (master pushes, after `wasm` + `windows`) uploads `fohmixer-windows-<version>-<sha>`: one zip with `fohmixer-hub.exe` (release, real UI embedded), `FohMixer\`, the `scripts/fohmixer-pc` scripts, `VERSION` and `SHA256SUMS`. `gh run download <run> -n <name>` yields that zip. It is built by `New-FohBundle` in `FohmixerPc.psm1`, the module the install itself uses.
- **Install** (elevated Windows PowerShell 5.1 on the PC, e.g. over MCP): unzip the bundle to a temp folder, then `powershell -NoProfile -ExecutionPolicy Bypass -File <unzipped>\Install-Fohmixer.ps1 -BundleZip <zip> -BandUser <band account> -MasterUser <master account> -Layout <import output>\layout.json`. The account names, host and paths are passed at run time and never enter the repo (`public-repo-hygiene.md`). `-BandUserLibrary` / `-MasterUserLibrary` when Live's User Library is not `C:\Users\<user>\Documents\Ableton\User Library`. Every input is checked before anything changes; a second run writes nothing (it does restart the hub). Errors: one `fohmixer install FAILED: …` line on stderr, exit 1.
- **What it writes** (`-DataDir`, default `C:\ProgramData\fohmixer`, protected DACL: SYSTEM, Administrators, the band user Modify): `app\<version>\` (the unzipped bundle; earlier versions stay), `app\current.txt`, `fohmixer-hub.toml` (no `data_dir` key: the hub refuses unknown keys), `layout.json`; the hub adds `secrets\`, `layout-backups\`, `logs\hub.out.log`/`hub.err.log` (+ `.prev`), `logs\hub-launch.log`, `logs\hub-stop.log`. Per Live user: `<User Library>\Remote Scripts\FohMixer\`, replaced only when `version.py` differs (Live's `logs\` stays), `Config.py` INSTANCE/PORT always per user. Live's preferences and a running Live are never touched: the user selects `FohMixer` in a slot and restarts Live (owner present, design note §4.2).
- **The hub has no `--config` and reads `FOHMIXER_DATA`** (not the design note's `FOHMIXER_HUB_DATA`; default: the working folder). A task action cannot set an environment variable, so the task `\fohmixer\fohmixer-hub` runs `Start-FohmixerHub.ps1` (hidden powershell), which sets it, starts the hub in its own windowless console with its output in `logs\`, and waits for it.
- **Stop = Ctrl-Break, never Task Scheduler's End (spec I7).** End has no graceful request for a process without a window, only a hard end; both tasks are registered with `-DisallowHardTerminate`. The install runs the task `\fohmixer\fohmixer-hub-stop` (`Stop-FohmixerHub.ps1`, in the band user's session: a console is reachable only from its own session), waits up to 10 s, and fails — never kills — when the hub stays up. `check_integrity.py` bans force-kill verbs in these scripts, comments included.
- **PIN:** the pepper is DPAPI for the hub's user, so `fohmixer-hub pin set-engineer` must run **as the band user** with `FOHMIXER_DATA=<DataDir>` (PIN on stdin, design note §4.5).
- **Rollback:** deselect `FohMixer` in the Live slot; `Disable-ScheduledTask -TaskPath \fohmixer\ -TaskName fohmixer-hub` and the stop task; `app\<older version>` is still there to reinstall from.
- **Self-test:** `Test-Fohmixer.ps1 -HubExe target\debug\fohmixer-hub.exe` in the `windows` job: parses every script, builds a bundle from the checkout, runs `-NoTask` installs as separate `powershell.exe` processes into temp folders (idempotence, port change, version bump, refusals), starts the real hub through the launcher and stops it through the stop script, registers both tasks in a unique test folder and reads them back, checks the DACL. Keep the scripts Windows PowerShell 5.1 and ASCII only (no `??`, `?.`, ternary, `utf8NoBOM`); nothing here compiles or runs PowerShell locally (Tier 0, no `pwsh` on the dev box), so CI is the check.
