# Remote access (#17): one name for the LAN and the Cloudflare tunnel

Design and owner decision: #17 (the `Design-by: main` comment and the `ROZHODNUTÉ`); spec §2.4 "Remote access", D7, R5. Ported from restreamer (`access.rs`, `.claude/rules/access-control.md`), iemmixer (the rustls listener, `tunnel_watch.rs`), airuleset (`cli_webterm_access.py`, `cli_webterm_pwa.py`).

## Invariants — never regress

- **The plain-HTTP listener (8480) always runs** and is never redirected by IP: it is the emergency path (`http://<PC IP>:8480`, no DNS, no certificate) and the tunnel's origin. A taken HTTPS port never stops it: `lib.rs` `start_https` reports the bind error in `/api/status` (`remote.https.bind_error`) and retries the bind every `HTTPS_BIND_RETRY` (1 min). `routes::redirect_target` redirects only a request for the `[tls]` name with no proxy header (a tunnel request redirected would loop), and only while HTTPS serves (before the first certificate the bound socket accepts nothing). The redirect is 307 (browsers do not keep it).
- **LAN is never authenticated and the `Local` branch of `access::decide` does no network I/O**: with the internet, Cloudflare or the tunnel down the mixer still opens. Never move a key fetch above the classification.
- **A request is `Internet` when it carries any `PROXY_HEADERS` (cloudflared connects from 127.0.0.1: the header decides, not the address) or its peer is public.** RFC 1918, CGNAT and link-local are `Local`. A LAN client that sends a forwarded header only makes itself need Access (the safe direction). **One list (#90):** `access::PROXY_HEADERS` (`is_proxy_header`; an entry ending in `-` is a prefix) is both the Internet signal and what `ableset::strip_request` takes out: every `cf-*` (Cf-Ray is on every request Cloudflare's edge passes on and no Transform Rule removes it, so a tunnel request a rule left without its forwarding headers still counts), every `x-forwarded-*`, `forwarded`, `x-real-ip`, `true-client-ip`, `cdn-loop`, `via`. Never add a header to one use only. (A separate loopback origin port for the tunnel, where everything is the internet, is PR D's.)
- **`set_required_spec_claims(["exp", "aud", "iss"])` is load-bearing:** `set_audience` / `set_issuer` check a claim only when present.
- **Without `[access]` every internet request is refused** (default deny). The engineer PIN stays behind Access everywhere.
- **The Access and Origin middleware sit inside `router()` after the routes are merged**, so the SPA catch-all `/{*path}` is covered; `check_host` runs first (421), then the redirect (HTTP listener only), then Access (403). `host_allowed` takes a name or an address plus an optional `:<digits>` port and nothing else. Since #9 anything after the address is a 421: `[::1] x`, `127.0.0.1:1 x`, an empty or non-digit port. Such a Host would pass the Origin guard with a matching Origin. `routes::host_name` is the one Host parser, and `host_allowed` and `redirect_target` both read the Host through it. Never split a Host by hand. A WebSocket upgrade is a GET exempt from CORS: the Origin guard checks it explicitly.
- **Both listeners bound a request head (#90): `lib.rs` `HEADER_READ` (120 s) through `http1_limits`, the one place their HTTP/1 settings live.** The plain listener runs on axum-server for it, as HTTPS does (`axum::serve` takes no settings). hyper counts the bound from when a connection waits for a head, so it is also the idle keep-alive bound: keep it above cloudflared's 90 s origin pool (a connection closed under the tunnel's reuse can fail a POST); a real phone's head is a packet or two, and axum-server bounds a TLS handshake at 10 s. **What it does not bound:** a connection that never sends a byte (after the TLS handshake on HTTPS) or only part of HTTP/2's 24-byte preface (hyper-util's auto builder reads that far untimed to choose the protocol), and an HTTP/2 connection (no head timer). **Never `http1_only()`** (axum-server's) to close that gap: it serves without upgrades, which ends every WebSocket, the mixer's `/ws` and AbleSet's tunnel. hyper-util's own builder-level `http1_only()` would not close it either: `serve_connection_with_upgrades` ignores the builder's version and always reads the preface (`server/conn/auto`); only a timer around a connection's first bytes (a listener wrapper) can. A host is read by `routes::request_host` (the first `Host`, else the target's authority: HTTP/2 has no `Host`) in `dispatch`, `check_host` and the redirects.
- **Missing `ConnectInfo` counts as the internet (fail closed):** a listener that lost it refuses everything (reason `no_peer_address`, even with a valid Access token) instead of letting a port-forwarded peer in. Both listeners serve `into_make_service_with_connect_info::<SocketAddr>()`; the router's `oneshot` tests add the peer as `axum::Extension(ConnectInfo(addr))` (`routes.rs` `lan()`; never `MockConnectInfo`: only the `ConnectInfo` extractor reads it, the Access middleware reads the extension itself, so every request stays "internet"); every plain-HTTP process test and `tests/remote.rs` `the_access_check_is_live_on_the_real_listeners` (a LAN request over TLS answers 200) break if a listener drops it.
- **Service worker and Wake Lock only on `location.protocol === 'https:'`** (index.html), not on every secure context: `http://127.0.0.1:8480` is one too, and the emergency path and the whole E2E suite use it. `sw.js` is network-only: never the Cache Storage (the `wasm` CI job greps for it). So a reload always fetches the current bundle, and since #26 an open page reloads by itself when the hub's hello names another build than its own (`net::on_hello`, under the once-a-minute `may_reload` guard): after a deploy the hub restarts, the socket reconnects, and a Home Screen app is on the new bundle without anyone closing it.
- **The wake lock is asked for again at the end of every touch (`pointerup`, capture, passive) while none is held (#5 K4), besides load and `visibilitychange`.** iPadOS refuses a request without user activation, and a finger's `pointerdown` is no activation (the HTML standard counts it only for a mouse; a finger activates at `pointerup` / `touchend`); the real iPad's client report said `wake_lock="denied"` before this change. Whether iOS WebKit activates at a touch's `pointerup` is closed code: only the real iPad's client report after a touch proves it (if it still says `denied`, ask on `touchend` for touches — adding `touchend` next to `pointerup` would not help, the refused request would still be pending). `data-wake-lock` is written only when it changes, since `diag.rs` reports every write. The E2E uses `stubWakeLock` with `{ activation: true }`, which grants only as the standard does (`pointerdown` would pass Chromium's mouse and fail the `ipad` finger), and `removeWakeLock` + `recordWakeLockWrites` for the one write of `unsupported`.
- **The LAN DNS entry of the public name is a CNAME to a local-only name, never an A (#26).** A static A answers only A locally: AAAA and HTTPS (type 65) go upstream, and Cloudflare's HTTPS record carries hints (`ipv4hint`/`ipv6hint`, ECH, h3). iOS follows them, so system traffic and Home Screen apps went through Cloudflare Access (and asked for its login) while Safari went straight (#9 comment 5886119292). With a CNAME to a name only the router knows, every type of the public name is answered locally: A with the PC's address, AAAA and HTTPS empty. `scripts/check_lan_dns.py --name <public name> --resolver <LAN resolver>` checks exactly that (a stdlib DNS client; FAIL, one line each, for an A answer without an address, a public A/AAAA, or any HTTPS record, named with its hints / ech; name and resolver are run-time values, never committed); `.claude/rules/deploy-pc.md` runs it after every deploy.
- **Secrets:** the Cloudflare API token (`fohmixer-hub cloudflare set-token`, stdin) and the ACME account key are sealed with DPAPI for the hub's user (`sealed.rs`) — so the command runs **as the band user** on the PC, like `pin set-engineer`. The TLS key is a plain PEM in `<data>/tls/` under the data folder's protected DACL. The tunnel's connector token lives in `<ProgramData>\fohmixer-tunnel\tunnel-token` (SYSTEM + Administrators only, `--token-file`), never on a command line. None of them is ever logged or printed.
- **AbleSet's name (#90) has its own certificate on the same listener, never one shared with the `[tls]` name.** `[ableset] name` is one label beside or under the `[tls]` name (`config::same_site_name`), never in `trusted_hosts`. `tls::SniCerts` serves its certificate (`<data>/tls/ableset/`) only for that SNI; any other name and no SNI at all get the `[tls]` name's (rustls's `ResolvesServerCertUsingSni` answers none there). `Https::set_cert(slot, …)`: only the `[tls]` name's certificate starts the server (AbleSet's waits), a pair that does not go together is refused before anything changes, and a renewal of one slot rebuilds the config with the other kept. Each name has its own status (`remote.rs` `NameState`; `/api/status` `ableset.cert`), so nothing about AbleSet's certificate shows on, or replaces, `remote.https`.
- **AbleSet's name is routed by `Host` before any of fohmixer's layers (#90).** `ableset::dispatch` is the outermost layer of both listeners, and only with `[ableset]` (without it the router is the old one): a `Host` of the AbleSet name (`routes::host_name`, any port and case) goes to the AbleSet router, never to fohmixer's routes; anything else (a malformed Host too: `check_host`'s 421) to fohmixer's. The AbleSet router: the proxy (`ableset/proxy.rs`, upstream only `http://` on loopback, `config::is_upstream`: the hub is never a proxy into the LAN) behind `access::middleware` with a gate of its own (`ableset::access_cfg`: `[access]`'s team with `[ableset] access_aud`; none: the internet is refused, the LAN served; the config refuses an AUD fohmixer's `[access]` has), the plain listener's redirect once AbleSet's certificate serves (`routes::redirect_to`, never by IP or for a tunnel request), and on every answer `ableset::framing` (`X-Frame-Options` and AbleSet's own `frame-ancestors` out, `frame-ancestors 'self' https://<[tls] name>[:port]` in) plus `answer_policy` (every `Access-Control-*` out: no other site reads AbleSet; `Set-Cookie` through `host_only_cookie`: a `CF_*` cookie dropped, it would shadow fohmixer's Access cookie at the edge, `Domain=` taken off the rest; `nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`). An `http://` Location of AbleSet's name becomes `https://` (`frame_policy`) only where the browser is on https: the HTTPS listener and a tunnel request; the plain listener's LAN answer keeps it. Upstream go no hop-by-hop or proxy header and no `CF_Authorization` cookie, exactly one `Host` (the one the dispatch matched; `Connection` never names `host`, `origin` or `content-length`), and nothing is added (no `X-Forwarded-*`: AbleSet treats the hub as local, the owner's decision; fohmixer's rules are the lock). **The cross-site rule (#90):** a LAN browser opens AbleSet without its password, so after the Access check `ableset::refusal` refuses another site's request that is no navigation (`Sec-Fetch-Site: cross-site` without `Sec-Fetch-Mode: navigate`: 403 `cross_site`; a link, a bookmark and fohmixer's iframe pass), CONNECT/TRACE (405) and a target that is no path (400), none of them an outage. **Limits:** `MAX_REQUESTS` (64) with AbleSet at a time, each slot held until its answer's body ends (`held`), one more 503 at once; warn lines at most one per `WARN_GAP` (10 s) per kind (AbleSet's own faults, everything else: a client's faults never hide AbleSet's), and an `ableset_proxy` record is warn class (`error`) only for a warned fault of AbleSet itself, else `why`, under the event log's daily cap; a client's fault (anything but `Failure::is_ableset`) is recorded at most `FAULT_RECORDS` (1) per `Failure::kind` per `WARN_GAP` (`ration::Ration`, the count left out as `skipped` on the next; AbleSet's own every time, `skipped` 0), so a looping client never uses up the day's space (#90 B3h). `events::is_warn` keeps only that warned outage record past the cap: never a client's fault, never an `ableset_ws` open or close (whose text is `why`, never `error`). fohmixer's own answers keep `X-Frame-Options: DENY`; `lib.rs` `page_csp` adds AbleSet's origins to `img-src` and `frame-src` only with `[ableset]`. **The WebSocket tunnel (#90 B2):** an HTTP/1.1 GET whose `Connection` names `upgrade` and whose `Upgrade` names `websocket` (`ableset::is_upgrade`; the `Upgrade` test is `access::is_websocket_upgrade`, the Origin guard's own, any value or list, so no upgrade the tunnel or axum's `WebSocketUpgrade` would switch skips the guard; an HTTP/1.0 one goes as a plain GET: hyper offers no upgrade there), after the same Access check and refusals, and refused 400 `ABLESET_UPGRADE_BODY` before it takes a slot when it announces a body (`upgrade_body`: a `Content-Length` other than 0 or any `Transfer-Encoding`; a handshake has none, and hyper hands no connection over before a body is read, so it would hold a connection to AbleSet as long as the page holds its own), goes to AbleSet with the pair put back after the hop-by-hop strip (`upgrade_headers`; every `Sec-WebSocket-*` passes, so subprotocols and compression are AbleSet's and the page's); on AbleSet's 101 the page gets that 101 and `AbleSet::carry` waits for both upgrades (`upgraded`, within the proxy's head bound, `HEAD_TIMEOUT`), then `pipe` copies each way on its own (`pass`: `tokio::io::copy` into a counting writer, then the source's close passed on as a shutdown; a TLS page's `UnexpectedEof` is its close, `source_closed`), never re-framing a byte. **Never `copy_bidirectional`:** it ends only when both ways reached EOF, so a page that stays silent after AbleSet's close (a suspended tab on a tablet that then leaves the Wi-Fi: nothing in flight, no TCP timer) held its slot for good (#90 review 1). Once one way ended the other gets `HALF_CLOSE_GRACE` (5 s: RFC 6455 §7.1.1, the client closes right after the server; two retransmissions at the 1 s minimum RTO), then both ends are dropped; `why_ended` (pure) names it in the record (`closed`, `<way>: <error>`, `the page did not close within 5000 ms of AbleSet's close`). **A stalled write ends it, never idle time (#90 B3h):** `Counted` fails a write, flush or close to one end that made no progress for `STALLED_WRITE` (60 s; any progress starts it afresh, an idle tunnel has no write waiting), so a page that never reads (zero window) no longer holds the write, and AbleSet's close behind it, for good; then the grace. 60 s against AbleSet's ping (design §3.4): AbleSet 3.1.5 pings every 2 s and closes after 10 s without a pong (Socket.IO's defaults: 25 s + 20 s), so a page no byte reached for a minute is already closed by AbleSet, and a live one takes bytes far more often; never shorten it below the ping's 45 s. Its tests run on tokio's virtual clock (`start_paused`, dev `test-util`). An upgrade AbleSet answers otherwise goes back as it came, holding its socket slot until its body ends (`held`); one AbleSet reads and closes unanswered is `Failure::Closed` (502 `ABLESET_CLOSED`, the client's fault: no outage, `proxy::failure`; a connect error stays `Down`). An upgraded connection is no longer the listener's: its graceful drain never waits for one, so `HubInner::stop` calls `AbleSet::stop` (a `watch`: open tunnels and any opened later are closed, both ends shut together within `CLOSE_BOUND`), and `serve_until` waits for every slot to come back (`HubInner::ableset_closed`, `AbleSet::closed`, `CLOSED_WAIT`, a warn line past it): the binary's runtime shutdown would cut a close and its record. At most `MAX_SOCKETS` (64) taken slots, their own semaphore (not `MAX_REQUESTS`), each held until the tunnel's close record is written (or a non-101 answer's body ends); one more is 503 `ABLESET_BUSY`; `/api/status` `ableset.sockets` counts the taken slots. Each open and close is an `ableset_ws` record (`ws_fields`: the tunnel's own number as `client`, `ws::opener`'s peer, forwarded client, source and origin; at the close `ms`, `up`/`down` bytes (counted as they go: also on an error and the stop), `why`) with an info line, at most `WS_RECORDS` (8) per kind per `WARN_GAP` (`ration::Ration`, the count left out as `skipped`), else a debug line. Tests: `ableset/tests.rs` (a fake AbleSet with a WebSocket echo, `/gone` that closes at once, `closer()` that reads a head and closes, the JWTs of `test_keys.rs`; `pipe` on `tokio::io::duplex` ends with a short grace, `Stuck` for a close that never goes out; the tunnel over real listeners: axum-server with `ConnectInfo` and `http1_limits` for plain HTTP, `Https` with a test CA for TLS and SNI, tungstenite as the page; the upgrades' bound only in the unit test: an announced body, the one way to build a page whose upgrade never completes on loopback, is refused 400 now), `tests/remote.rs` (the stop through `serve_until`: a TLS page on a 4 KiB receive buffer that never reads, so its close takes the whole `CLOSE_BOUND`).

## ACME (`acme.rs`)

- `keep` loop, one per name (`bind_https`: the `[tls]` name's, and AbleSet's with `[ableset]`, #90; each with its own store `CertStore::slot` and status): a stored certificate for the name with ≥ 30 days is kept (checked every 12 h); otherwise one attempt; a failure is in `/api/status` (`remote.https.acme_error`, `acme_failures`; AbleSet's in `ableset.cert`) and retried after `next_attempt` (1 min doubling to 6 h; without a Cloudflare token every 5 min, warned of once: `warns`) while the old certificate keeps being served.
- **The keepers take turns (#90):** one `tokio::sync::Mutex` (`Acme::turn`) is held for a whole attempt, so a fresh data folder gets one account and the two DNS-01 runs never overlap in the zone. An attempt is cut off at `ATTEMPT_LIMIT` (30 min, far beyond a slow one that works): instant-acme's requests have no time limit of their own, and without the cut a CA that never answers for one name would hold the other name's renewal back for good. Nothing about AbleSet's name re-issues, replaces, removes or holds back the `[tls]` name's certificate: `acme/tests.rs` pins it (`a_failing_ableset_order_…` for a DNS-01 error, a rate limit and a wrong zone; `a_failing_tls_name_order_…` the reverse; `an_attempt_that_never_ends_…`), with the ACME double refusing one name only (`refused`, `rate_limited`).
- DNS-01: zone found by the longest parent the token sees (`cloudflare::zone_candidates`); leftover `_acme-challenge` TXT records of this hub (comment `TXT_COMMENT`; another client's records are never touched) are deleted first; the record is removed after the check **also on failure**; `propagation_s` (default 20) before answering the challenge. A valid authorization the CA still holds for the account (Let's Encrypt: 30 days) needs no record: `AuthorizationStatus::Valid` is skipped (the double reuses one).
- The account is per directory: switching `[acme] directory` (staging ↔ production) makes a new account; a stored file that does not parse is logged and replaced (`stored_account`).
- A plain-`http://` directory is only allowed on loopback (`config::url_allowed`) and is what the tests use (`acme/double.rs`, an RFC 8555 double that checks the JWS signatures and the TXT record against the key authorization; `cloudflare::double`).

## Tests

- RSA keys for Access JWTs come from `openssl genrsa -traditional` (`test_keys.rs`): the `rsa` crate carries an unfixed advisory (cargo-deny), ring cannot make RSA keys. Token-shaped test values are low-entropy (`"t".repeat(24)`): gitleaks reads a realistic one as a leak.
- `tests/remote.rs` talks TLS with tokio-rustls and SNI (no DNS needed); the CA and leaf come from rcgen. Unit tests use `tls::test_certs::handshake` (trusts one CA, returns the served certificate's names and end; `handshake_sni(…, false)` sends no SNI): a certificate swap or "the old certificate still serves" is proven over TLS, never by `serving()` alone, and a client that checks the name proves which slot's certificate was served.
- E2E (`remote.spec.ts`): the `e2e` job makes a per-run CA + leaf for `foh.e2e.test`, trusts the CA in the system store (WebKit/GnuTLS) and the NSS db `~/.pki/nssdb` (Chromium), maps the name in `/etc/hosts` (Chromium's `--host-resolver-rules` would not reach WebKit), and an RSA key whose public half the harness serves as the team's key set (`--access-key`). A request "from the internet" is one with `cf-connecting-ip`. The Wake Lock is stubbed (`stubWakeLock` in `e2e/tests/support/pwa.ts`, shared with `client-report.spec.ts`: headless browsers hold none); what is tested is the page's acquire/re-acquire logic.

## On the PC and at Cloudflare

- Installer (`FohmixerRemote.ps1`, only with `-PublicName`; `Install-Fohmixer.ps1` calls `Resolve-FohRemote` and hands its plan to `Invoke-FohInstall -Remote`): `[tls]`/`[acme]`/`[access]`/`[tunnel]` in the toml, the hosts block (`# BEGIN fohmixer … # END fohmixer` → 127.0.0.1, in the file's own encoding), the band user's desktop shortcut `fohmixer.url`, firewall `fohmixer-hub-https` (`FohmixerFirewall.ps1`), and with `-SetTunnelToken` (token piped on stdin) the service `fohmixer-tunnel` (`--protocol http2`, metrics 127.0.0.1:20241). Refused before any change: a config the new hub refuses — every install writes the toml text to the unpacked bundle and runs its `fohmixer-hub config check <file>` (`Test-FohHubToml`, `Config::check_file`: config.rs is the one set of rules, never re-implemented in PowerShell; the e-mail `is_email` and the AUD tags `is_aud` included, values written as escaped TOML strings so the hub checks exactly what was given) —, `-HttpsPort` taken by another program (`Test-FohPortFree`), a cloudflared without `tunnel run --token-file` (`Test-FohCloudflared`), a remote-access parameter without `-PublicName`. An install without `-PublicName` keeps the installed remote tables (`Get-FohInstalledRemoteToml`) and touches nothing else of it. An older `Cloudflared` service on the PC is never touched.
- Cloudflare side: `scripts/cloudflare/fohmixer_cloudflare.py` (dry-run by default, `--apply`): tunnel, Access app + policy (before the name is published), ingress → `http://127.0.0.1:8480`, proxied CNAME; prints the hub's `[access]` table; `--token-out` writes the connector token owner-only. A healthy public name answers **302** to the Access login, not 200.
- Router: a static DNS record of the name → the PC's LAN IP (MikroTik, its own project's workflow), as a CNAME to a local-only name that has the A (see the invariant above; checked by `scripts/check_lan_dns.py`).
