# Presenter's stage tab (#90; the owner's approved `docs/mockups/presenter-stage-v1.html`)

Decisions: #90's DESIGN comment of 2026-11-08 (the main session's) and the lane's DECIDED of the same day (the root paths, reads only; WHEP through the proxy by the owner's ruling of 2026-11-09).

- **Presenter's stage page lives on fohmixer's own origin, at Presenter's own root paths.** Its WASM shell picks itself by `location.pathname == "/stage"` and calls root paths (`/stage/…`, `/stage-displays`, `/live/ws` built from `location.host`, assets under `/ui-pkg/`, Trunk's `public_url`), so a path prefix renders "Page not found". `presenter::EXACT` / `UNDER` are the list (read from Presenter's source, `presenter-ui/src/{lib.rs,api/stage.rs,ws/stage.rs,components/stage/*}`), passed by `presenter::dispatch`, an outer layer of both listeners with its own host check, redirect, fohmixer's Access check (its Origin guard too) and `frame_headers` (`X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'`): fohmixer's own `X-Frame-Options: DENY` layer would otherwise block the frame. Those layers are the only ones on these paths, so `tests/it/presenter.rs` and `tests/it/remote.rs` pin each (403 for the internet without Access and for another site's socket, 421 for a foreign Host, the 307 of the public name on the plain listener). **Presenter's content runs on fohmixer's origin, where the page's token lives:** only the stage page and its assets run as a page (`runs_as_page`); every other answer carries `SANDBOXED` (`sandbox; default-src 'none'`: a library's HTML or SVG opened as a document runs on an opaque origin, a fetch ignores it), and no answer passes `ORIGIN_WIDE` (`Clear-Site-Data` would wipe the token, `Service-Worker-Allowed`, `Refresh`). A new path the stage page starts to load goes into the list; never a catch-all.
- **Reads, and the stage's video:** GET/HEAD, the `/live/ws` upgrade (AbleSet's byte tunnel, `ableset::pipe`/`upgraded`, made `pub(crate)`) and Presenter's own write routes with exactly their methods (`presenter::writes`, `Writes::{Post, Session}`, read from Presenter's `crates/presenter-server/src/router.rs`): `POST /ndi/whep/{source}` (the SDP offer), `POST|PATCH|DELETE /ndi/whep/{source}/{session}` (re-offer, ICE, end), `POST /ndi/client-stats` and `POST /ndi/sessions/{session}/client-stats` (the stage page's stats); every other route under `/ndi/` is GET there. The owner ruled on #90 (2026-11-09) that the preview shows what the stage displays show, video included (fohmixer's origin is behind Access and the token). **Read Presenter's router before opening a write:** 1.38.0 opened `/whep/`, a path Presenter has no route for, and the PC's video got 405 (`connect_whep failed: WHEP POST returned 405`; fixed in 1.38.1, which also took `/whep/` out of `UNDER`: it is fohmixer's own path again). A route is matched by its segments after `/ndi/`, none empty (the query apart); a new route of the stage page's goes into `writes`, never a prefix. Bodies and their `Content-Type` (`application/sdp`, `application/trickle-ice-sdpfrag`, JSON) pass as they are, the query too (`?profile=compat`), at most `MAX_BODY` 64 KiB (an announced longer one 413 before anything reaches Presenter, `announced_over`; a streamed one cut by `Limited`, 413; a body the page broke off 400, never "Presenter down": `presenter::failure`); a write route's path with an encoded `/` or `\` (`%2f`, `%5c`) is 400, whatever the method (`encoded_separator`: Presenter decodes a source's or session's name). Presenter answers the offer with a relative `Location` (`/ndi/whep/{source}/{session}`, `presenter-ndi` `manager/whep.rs`), which passes as it is; an absolute (or `//host`) `Location` at Presenter's own address, and any absolute one under `/ndi/whep/` (`presenter::WHEP`), becomes its path on fohmixer's origin (`local_location`, on every proxied answer; a port left out is the scheme's). Any other method 405 (`Allow: GET, HEAD`; on a write route the route's, `Writes::allow`), another upgrade 400, a dot segment (plain or `%2e`) 400, all by the hub. Presenter has no login: its write API must never be reachable through fohmixer. `tests/it/presenter.rs` `the_stage_video_starts_and_ends_through_whep_and_nothing_else_is_written` (the fake's routes are Presenter's: `/ndi/whep/{source}` answers 201 with Presenter's relative `Location`, and an absolute one for the source `absolute`). The video's media (ICE/RTP) goes between the iPad and Presenter's PC directly, never through the hub: on the LAN it plays; whether it plays over the internet path is the live check's. The socket is a byte tunnel both ways: Presenter's live socket takes only a stage display's presence, heartbeat, diagnostics and goodbye from a client (`presenter-server/src/live.rs` `InboundMessage`, read 2026-11-08), nothing that changes the stage; a new inbound message there would change this. The one write is the hub's own `POST /stage/layout` (`presenter::link::Api::switch`, user agent `fohmixer-hub/<version>`).
- **The link** (`presenter/link.rs`): one session = the socket `/live/ws?surface=fohmixer&preview=1` (a preview is never counted as a stage display), then `GET /stage-displays` + `GET /stage/layout` (after the socket, so no switch is missed between), then each `{"type":"stage_layout","code"}`; ping every 5 s, 15 s with no frame at all ends it (a timer of its own in the `select!`, counted from the last frame, a pong included: a `timeout` around `next()` made afresh each turn was restarted by every ping tick and never fired, #90 review; `presenter/link/tests.rs` pins both on a paused clock with a silent and a pong-only server), `RETRY` 2 s. Up/down is AbleSet's `link_step` (down after 2 failures in a row: a session's end and the next failed try), a `presenter_link` record (warn class). `RouterMsg::PresenterLink` → `router/presenter.rs` tells every page `ServerMsg::Presenter {online, layouts, current}` only on a change (kept while down).
- **A switch:** the page's `presenter_switch {code, seq}` → `switch_refusal` (not up, not listed, longer than `MAX_CODE`) or the switch task → `RouterMsg::PresenterSwitched` → the page's `presenter_ack` and one `presenter_switch` record (`client`, `peer`, `code`, `from` = the layout on stage when the page asked, carried in `SwitchRequest`: Presenter's own event often comes before its answer; `ok`, `on_stage` or `error`, `ms`, none when the hub refused). Never queued, never resent. One switch on its way per page (`in_flight`, a refusal frees nothing). The layout on stage comes only from the link's events (Presenter tells every switch on its socket, the hub's own too), never from a switch's answer: an answer can arrive after a newer switch's event (`a_late_answer_never_puts_back_an_older_layout`). Refused and failed switches' warn lines are rationed (`SWITCH_LINES` 8 per 10 s).
- **The UI:** `Extra::Presenter`, `PresenterTab` in `surface.rs` (under IEM MIXER's row), `PresenterView` over the left half. The preview frame (no `sandbox`: one with `allow-scripts allow-same-origin` is liftable by a same-origin frame, and both engines warn of it on the console, which the guard fails) is mounted only while Presenter is up (`behave::presenter::preview`), 1920 × 1080 scaled by the measured width, `pointer-events: none`. The stage area has an explicit `width` (`calc(100% - 20px)`), never a stretched width with margins: WebKit took the 16:9 height from the pane's width before the margins (17:10, measured). The keys are `components::hold_key::HoldKey` (the rail's `rail_press`, shared with the REC/ARM keys): `can` decides the fill, `wanted` what the lift switches to, `act` sends it; `release — switch` shows from `data-full` in CSS; dim keys take no touch (`pointer-events: none`).
- **Tests:** `tests/it/presenter.rs` with the in-process fake `support/presenter.rs` (`?refuse`: a 403 instead of the switch; `?flood`: 64 KiB frames as fast as they go, so a TLS page that never reads makes the stop's close take its `CLOSE_BOUND`: `tests/it/remote.rs` pins that `serve_until` waits for it, `presenter_closed`); an event record is on disk only once the log's writer thread wrote it, so a test polls for it (5 s), never reads once (the `test` job's `cargo test` run missed it); the E2E harness's `fake_presenter.py` (`--fake-presenter-port`, CI 39195; control `/presenter/{down,up,switch,clear}`, `GET /presenter`); `e2e/tests/presenter.spec.ts`. Locally: the harness on ports below 32768 (the ephemeral range is not reserved on the dev box), `PLAYWRIGHT_BROWSERS_PATH=/opt/ms-playwright` (never `playwright install` in the account), `NODE_OPTIONS=--experimental-websocket` on Node 20 (`LiveClient`).
- **The column's stage miniature (1.37.0; way A of the owner's approved `docs/mockups/presenter-stage-v2.html`, #90's ROZHODNUTÉ of 2026-11-09):** the same `StageFrame` as the pane (`Place::Pane` / `Place::Column`: its class, test id and recorder steps `frame`/`load` or `mini_frame`/`mini_load`; never a copy), mounted by `StageMini` inside `.rail` between `.rail-main` and `.rail-foot` (TECHALERT) on both pages (`surface.rs` PageView, `sectors.rs`). Its size (since 1.38.2, #90's DECIDED of 2026-11-09 evening, option A: the owner's iPad in Safari over the internet never showed it, the old rule hid it wherever the rows needed the room) is `behave::presenter::mini_picture` over the measured rail (`RailRoom`: the rail's width, its box less its foot and the 6 px gap, the rows from `.rail-main`'s resolved `grid-template-rows`, `track_count`; `RAIL_ROW`/`RAIL_ROW_GAP`/`RAIL_GAP` mirror `page.css`, `MINI_EDGE`/`MINI_CAPTION`/`MINI_CAPTION_GAP` mirror `presenter.css` `.stage-mini`: change them together): 16:9, the rail's width less its box at most, as high as the room the rows leave at their full 44 px (a whole px when the room cuts it), never under `MINI_MIN_PICTURE` 40 px: below that the rows give the room up (their `minmax(24px, 44px)` shrinks them, the 24 px floor and the rail's scroll past it are `page.css`'s), the faders never. `mini_fit` decides in this order: no `[presenter]` (or not told yet), PRESENTER open, a phone, the rail not measured, else shown (`MiniHide::Room` only for a rail with no width); the picture narrower than the rail is centred under the caption. Measured locally with the CI harness (the fixture's 8 rows): full size with 44 px rows at 1194 × 834 (117 px spare), the least picture with rows of about 38 px at 1180 × 740 and about 33 px at 1024 × 700 (there the rows were 41.9 px even without it), in both engines. Measured unrounded (`getBoundingClientRect`) by a `ResizeObserver` on `.rail` and `.rail-foot` (the rail's size never depends on the miniature: it is `flex: 1` in the column; the first measure can come before the column settles, so a page's first `mini_fit` may read a taller rail); the rail's rows are not observed: every source of new rows (a new layout) remounts the page, and so the miniature, today: a rail that gains rows in place needs an observer on `.rail-main`'s rows too. **The recorder's `mini_fit`** (essential `presenter` event, `PresenterStep::MiniFit`, at each change of the decision but before the hub told of Presenter or the rail was measured, `mini_fit_noted`): `vw`/`vh` the viewport, `rail_w`/`room`/`rows` the rail, `w`/`h` the picture or `hide` (`open`, `phone`, `room`), lengths to 0.1 px: the next report of a missing or tiny miniature is read from the hub's event log. The miniature is never on a phone (`phone`, the 520 px queries; `page.css`'s backstop hides it), never while PRESENTER is open (one stage page on the iPad, not two), not at all without `[presenter]`. Rendered only when shown (no box, no gap otherwise). The specs set the viewport: `presenter.spec.ts` checks 1194 × 834 (full size, rows 44 px), 1180 × 740 and 1024 × 700 (the least picture or more, rows under 44 px and at least 24, the right half's faders as with PRESENTER open, the `mini_fit` record's size equal to the drawn picture), the phones and 521 × 1000. A dim `STAGE` caption with the layout's name (`mini_note`), `offline` red and a black box at 0.35 while Presenter is down (the frame unmounted, as the pane's); a tap (`pointerdown`, `use:owns_touches`) records `mini_tap` and opens PRESENTER. **It lives in the page:** a page's remount (another page's tab, the sectors switched, an ARRANGE save, a new layout) loads the stage page again (a brief black picture). Ruled on the review of PR #179: drawing it above the column from outside the page would put it over TechAlert's wash (the wash's z-index 50 lives inside the column's stacking context), and the frame holds no state to lose. **Every iPad-sized spec now has Presenter's stage page in a frame** (its own `/live/ws` through the hub and the link proxy): `HUB_SOCKET` matches the root `/ws?` only, and the fake stage page catches its fetch (`data-app="failed"`), so a dropped or blocked link gives no unhandled rejection. Its `/live/ws` tunnel ends with a bare TCP close at a hub restart; a WebKit `WebSocket connection to '…/live/ws…' failed` line in a restart spec is the miniature's: widen that spec's allowance to the root and `/live/ws` sockets, never to `.*`.
