# fohmixer-ui: where logic lives, and how it stays mutation-proof (#8)

## Pure decisions, thin browser glue

- Every decision is a pure, natively tested function or state machine: `behave/*` (TouchOSC behaviour and the redesign's scale, dB readout, colour, peak, SOLO ✕), `binding` (what is subscribed, the page selection), `arrange` (where the controls go, #63: lines, halves, the pager's region and its pins, the window and its arrows), `flow` (a control's kind, the instance a group names), `net` (handshake — a protocol the hub no longer serves or, since #26, a hub of another build, or since #90 a hub whose hello names another page policy than the `fohmixer-policy` meta this page loaded with (`policy_changed`: both known and different; the glue reads the meta with `dom::meta_content`) reloads the page, once a minute at most —, reconnect schedule, HTTP answers), `diag` (#26: the diagnostic report's fields, the throttle — one report per kind per 5 s, a change within the window sent once when it ends with the state of then, an error message once —, `connected` vs `reconnect`; which close is a lost connection is `Conn::closed`; #43: an `error` report's text first, as before (`ERROR_MAX_CHARS` 300), then the thrown value's stack, `error_text` / `stack_line`: the lines trimmed, the empty ones dropped, joined on one line by ` | ` after ` | stack: `, at most `STACK_MAX_LINES` 30 and `STACK_MAX_BYTES` 4096 bytes, the cut marked ` [cut]` within them; the whole `error` cut to `fohmixer_proto::client::REPORT_ERROR_MAX_CHARS` 4500, the hub's limit for it, a `const` assertion keeping the longest text and stack under it; the glue's `stack_of` reads an `ErrorEvent.error`'s or a rejection reason's string `stack`. `upload(now, ready, buffered, proof)` from the link's tick: a batch of at most 1 000 bytes, the `trace` envelope (`ENVELOPE`, 28 bytes) included, only when no set went since the previous tick (`set_went`, from `LiveStore::sent_set`), the socket holds at most 1 KB unsent (`takes_batch`: a ping still leaving never holds it — WebKit's `bufferedAmount` read above 0 at every tick for minutes, the PR C gate on 0 starved), the 10 KB/s cap (each batch waits its own bytes at that rate, `paced_until`: a full batch 97.7 ms, inside the 100 ms tick — counting the envelope outside the bound made it 103 ms, every second tick, half the rate; exactly 100 ms left no margin for a coarse clock) and it is due (a full batch — events that fill a message with their commas and the envelope — at once, less every 2 s (`upload_ms`: every `IDLE_UPLOAD_MS` 30 s while the page is idle, #51 PR 2c), `soon()` after a hello, a dropout, a reset); past 768 KB unsent (PR E: no batch goes during a drag, so a 30 s drag of two faders at 60 Hz, ~610 KB, waits whole and drains at the cap once the fingers rest, ~75 s; PR D's 48 KB lost every drag over ~4 s) events go by `drop_rank`, oldest first within a rank: rank 0 (`rtt`, `frame`, any other kind), then rank 1 (`mv`); A ping carries the latest pong's round trip and the number of the ping it measured (`rtt`, `rtt_n`; `Conn::ping`), reset on a new socket. The dropout watch ticks on its own 100 ms page timer (`LiveStore::tick_link`, `store/live/link.rs`), never on a socket's watchdog, so a socket lost during a page stall still counts from the next on-time tick; that tick also sets the counter's signal (`LiveStore::dropouts`, only on a change) and is the only place a recorder batch goes from (`upload`), so the writes and subscriptions a hello or an instance back sets off are on the socket first. Pure as well: `behave/idle.rs` (#51, the owner's decision of 2026-10-12: `IdleWatch`, Active or Idle: `visibility(now, hidden)` makes a hidden page Idle at once, `Sleep::Hidden`, and shown wakes it (`Wake::Visible`, the countdown starts over); `tick(now, after, held)` makes an untouched page Idle after `idle_after_ms(idle_after_s)` (absent or 0: never), `held` (a finger down, an open Pro-Q 4 screen, a pending EQ input) or touch-idle off starting the countdown over, and touch-idle switched off wakes it (`Config`); `touched` wakes a page idle for no touch, never a hidden one; `meter_ms`: 0 only for hidden, else `idle_meter_ms` or 250 when absent or 0; `Turn::event`, the essential `idle` record; `holds(finger_down, eq_open, eq_caught_up)`, touch-idle's `held`; `IDLE_FRAME_MS` 100, an idle page's frame pace, PR 2c), `behave/hold.rs` (#71: the press on a strip's ☰, below), `behave/deck.rs` (#52: a Stream Deck key's `Presses`: down at the first finger, up at the last lift with the page's hold and why — `up`/`cancel`/`lost`/`hidden`/`tab` —, a down that cannot go flashes and its up never goes, `leave_all` for the tab and a hidden page, `clear` on a closed socket, `missed_ups`: a primary pointer's down — the browser's `isPrimary`, no other pointer down — first ups every hold still recorded, `lost`, so an end the browser never delivered leaves no key stuck in Companion, as `diag/perf.rs` forgets a missed up; a second finger's down releases nothing), `store/deck.rs` (#52: `key_side`, the square key in the measured area; `DeckWaiting`, the downs waiting for their `deck_ack`, the page's own press numbers) and `pages/deck.rs` `half_keys` / `half_vars` (#52, #63: each half's keys around the column, its columns, the rows and the key side from the left `.deck-area`'s measured size).
- The glue carries decisions out and decides nothing: `store/live.rs` (socket, timers, signals), `store/live/idle.rs` (#51: a `visibilitychange` listener on the document, kept in `Inner` and removed at `stop`, and the link's tick for a missed change, through `IdleWatch::visibility`; a sleep sends `idle {on: true, meter_ms}` from the handler itself, before iOS freezes the page, a wake `idle {on: false}` and a ping at once (`Inner::ping`, the watchdog's too); each turn sets `Conn::set_idle` / `DropoutWatch::set_idle`, records `Turn::event` and writes `LiveStore.idle`, the surface's `data-idle` (nothing visible); `idle_hello` tells each hello's new outbox again; PR 2b, touch-idle: a capture-phase, passive `pointerdown` listener on the window, kept in `Inner.on_touch` and removed at `stop`, calls `IdleWatch::touched` (`touched`), so the wake is done before any control's handler sees the down: the window's capture phase runs before every element listener and before Leptos' delegated `on:` handlers; the link's tick calls `IdleWatch::tick` with the layout's `idle_after_s` read untracked (a new layout counts from the next tick) and `held` = `holds(diag::finger_down(), Inner.eq_frames.is_some(), eq_caught_up())` (`tick_idle`); a missed `pointerup` keeps a finger down in `Perf` until the next primary down, so the page stays Active: the safe side; PR 2c: each turn also sets `raf::set_idle` and `diag::idle` (the tested `Perf::turn` and `Recorder::idle`), and the store's stop calls `end_idle`: the frame loop back to full rate, and `diag::idle(false)` when the page was idle, so no pace outlives the store (the next one starts Active and never wakes)), `dom.rs`, `raf.rs` (#51 PR 2c: while idle, `schedule` waits `IDLE_FRAME_MS` on a timer, then asks `requestAnimationFrame`, so drawing stays on the display's frames; `MAX_STEP_MS` stays 100 = the pace, so a meter's fall keeps nearly real time), the components, `diag.rs`'s browser half (listeners, the keepalive POST to `/api/client-report`; the store calls `diag::connected` on a hello and `diag::disconnected` when a socket that said hello closes; `raf::tick` hands `diag::frame` every frame's gap (the glue stamps it with `dom::now`, the clock the reports and the throttle use — a rAF time is the frame's start and can lie before the last report's stamp), and capture-phase pointer listeners on the window count every pointer — a new measure of the page reads the one frame loop, never a second `requestAnimationFrame` loop that would keep drawing on a page with nothing moving). The glue is excluded from mutation in `.cargo/mutants.toml` one function at a time, with a reason. New logic that lands in glue is a finding: extract it into a pure function and test it (the #8 review found three bugs hiding in the old untested `LiveStore`; the #26 review moved "which close is news" into `Conn::closed`).
- **A tablet's behaviour is a diagnostic report, not a console line (#26):** a new browser event worth knowing is a new `diag::Kind` reported through `diag`; the hub log and `/api/status` `client_reports` are where a deploy check reads what a tablet does. A report's `fetch` is awaited so a failed one is no unhandled rejection (the console guard), and the hub answers 204 even over its budget.
- **A lost hub connection keeps the values (#43, L2):** the hub values (STAGE AUT) too since #104 (review M4): `store::HubValues` keeps them through a close, stale (`closed`; shown through `flag`, acted on only through `fresh_flag`), and the next connection's first `hub` message replaces them all (`put`: the hub sends every hub value at each attach, so a key it no longer sends goes). `on_close` turns each wanted slot with a value into `Slot::Stale` (`into_stale`); a stale slot is ready (the control is enabled and takes touches) and shows its value, the next value from the hub makes it fresh. I8's `Pending` stays for the first load, an instance reported offline and a key subscribed again while the hub is connected; a page switch goes through `Slot::rewanted(connected)` for the keys it adds and removes: `Pending` while the hub is connected, a known value kept stale during an outage (a page left and re-entered in the same outage still takes touches); each hello turns every slot no page wants `Pending` (`LiveStore::forget_unwanted`, `Conn::wants`), so a page left during one outage never comes back with that outage's value, and `LiveStore::apply` drops a value for a key no page wants (a `values`/`subbed` the hub sent before it read the unsub, late on a slow link: nothing would keep that slot current). A meter reads `Slot::fresh_number` (it falls, never freezes at a stale level) and the status light `Slot::is_fresh`.
- **A fader shows its open write (#43, L3, §4.3):** the frame loop asks `LiveStore::intent_view` for the first target's key (its state and open value) and tells `FaderCtl::intent(open, now)` and `write_at(law.pos(value))` before `frame`: while open the fader is local and, when no finger or glide drives it, sits at the write (a fader rebuilt by a page switch shows the write, not 0, and a touch starts from the cap); the close starts the post-release hold again. It writes `data-intent` (`confirmed`/`sending`/`unconfirmed`/`not_sent`) and, while the state `shows_ghost`, Live's position as `--g` with `data-ghost` (Live's value): the stylesheet `intent.css` (linked last) outlines the cap `--warn` / `--danger` and shows `.fader-ghost`, no text. The pan and the toggles (mute, solo, stage, param toggles) keep showing Live's value and get the outline only (#43 PR C): the pan's frame loop writes its key's `data-intent` (`LiveStore::intent_state`), a toggle registers `components::intent_look` (a frame function writing the `most_urgent` state of its keys, only on a change). A pointer's end goes through `behave::touch_end(drives, unsent)`: the unsent move as a final set, else `LiveStore::release` (the release time, L4); a glide's end (`FaderCtl::take_ended`) is a release too; a taken touch calls `LiveStore::touch`; a fader or pan taken away under a finger (`on_cleanup`) calls `release`. The pan records its release and touch the same way (`PanCtl::drives`, `LiveStore::touch` on its pointer down); toggles keep showing Live's value (P2), write final sets, and a tap inverts what the toggle shows (a write still on its way is not drawn on a toggle, so it is not what a tap inverts; round-2 review of #43). The write glue lives in `store/live/writes.rs` (`on_ack`, `resend`, `set`, `release`, `touch`, `intent_view`, `live_value`, the latter from `apply` through `store::write_key`).
- **A touch's first pointer move only anchors the drag (#43 PR F):** `FaderCtl::moved` / `PanCtl::moved` take the touch's first move (`first_move`, set at `press`) as the new `last_y` / `last_x` and move nothing (the iPad's first event comes ~83 ms late and 6–15 px away). `FaderCtl::anchoring(false)` keeps TouchOSC's first move: `FaderView` takes it from `Law::anchors` (the linear parameter faders, `Law::Linear`, do not anchor: the owner's call; the backing-tracks fader's targets are `Law::Volume` and anchor, #58). A native test that drags a ctl writes that first move itself (`anchor(&mut f, id, <down's y>, t)` in `behave/fader/tests.rs` and `behave/pan.rs`; a move at the down's own coordinate moves nothing on the old or new code), else its first move is swallowed. The tap check still counts the anchor's slide (`FaderCtl::slip`, cut at the ends when it came: `clamp(pos + delta) − pos`; `tap_pos` = position + slip within 0..1, for every move and the release): without it a quick nudge whose one event slid the finger was a tap, and two of them glided the fader to 0 dB (PR F review, round 1); uncut, a slide past an end that the next moves came back from was a tap again (round 2). `touch_start_tests.rs` pins each path apart (a late lift, a slide and back lifted at once or still, a nudge before a double tap, a slide past each end). The shaping's emergency / calm sizes are fractions of `REFERENCE_TRAVEL` = 355 px (TouchOSC's strip on the FOH iPad), not of the fader's travel: `finger_size` (ratio first, so 355 px is exactly the old behaviour) and `Shaper::set_travel` from `press`. The page reads `clientY` as whole px (web-sys `client_y()` is `i32`): on a 207 px fader 1 px is about 0.1 dB or more (0.12 dB at 0 dB, more lower down, 0.0995 dB only at the very top), so the forced first step needs TouchOSC's travel in a test. The touch's first `mv` carries `a` (`Trail::moved(pointer, at, c, pos)` with the ctl's `pos()` right after the move).
- **The flight recorder hears the page (#43 PR C, PR D):** every control's touch (`components::trace_touch`: up / cancel when `TouchEnd::ends_touch`, `lost` for a fader's, pan's or pulse toggle's touch a primary down of its type or a hide ended, #124, as the Pro-Q 4 screen's own recorder writes `eq_touch` `lost`; a toggle's `tap` (mute, solo, stage: no up follows), a param toggle's down and its up by `touch_end_name`, never the `lostpointercapture` after it); a fader's or pan's taken down with where it started (`FaderCtl::press` / `PanCtl::press` give `behave::Start`, `components::trace_start` with `Press { at: dom::event_epoch(&ev), c, travel }`), its moves (the component's `Trail`: `moved` with each pointer move's own time and coordinate when the ctl took it, `components::trace_move` after each send from the finger with the first target's `seq`, `LiveStore::set` returning it; `end` at the touch's end); a write's turn to `unconfirmed` or `not_sent` (`store/live/writes.rs` `note_intents`, PR E; a write the socket took calls `Recorder::set_went`; since PR E neither a send nor an ack is an event), each pong into the round-trip summary (`store/live.rs`), the socket transitions, and `diag::frame` / the visibility listener (`diag.rs`) go into `diag::record` (`record_essential` for a touch's first moves). The recorder is one per page (a thread-local in `diag.rs`, `with_trace` for the store's uploads).
- **The controls own their touches (#43 PR G):** every tap target's root carries the directive `use:owns_touches=keys` (`components::owns_touches`: `dom::prevent_on` with `sys::CONTROL_PREVENTS`, `touchstart`, and its write keys in `data-keys`, `sys::KEYS_ATTR`, JSON); the surface's root `use:owns_surface` prevents `sys::SURFACE_PREVENTS` (`contextmenu`, `selectstart`, `dragstart`); `.surface *` is not selectable, called out or draggable (`style.css`). Only an active `touchstart` listener stops WebKit's loupe of a tap followed by a hold (bug 231161); `dom::prevent_on` adds ONE shared closure (a thread-local, no closure per element; a directive run again adds nothing) with `passive: false` on the element itself, never a Leptos `on:touchstart` (delegated to the window, where Chromium makes a `touchstart` listener passive by default and `preventDefault` there is ignored with a console intervention). A new tap target gets the directive (pass `Vec::new()` bound to a name when it writes no key: no turbofish in a `view!` attribute; `scripts/check_integrity.py` fails any element of a component or page, login.rs aside, whose start tag has `on:pointerdown` without `use:owns_touches`); a new control never uses `click`, which a prevented `touchstart` suppresses, and the gate fails any `on:click` (or other mouse event: `dblclick`, `mousedown` … `mouseleave`, all of which a prevented `touchstart` swallows) in a component or page (the login keypad and the shell's Try Again are not surface controls and keep it). The page's own background (a line's half, the column) keeps its touches: never prevent `touchstart` above a control.
- **The Stream Deck tab (#52, `pages/deck.rs`, `store/live/deck.rs`):** the tab is `Nav.extra` = `Extra::Deck` (#90: `Extra { None, Deck, AbleSet }`, one extra tab at a time), never stored (a reload opens the last mixer page), written only on a change (`Nav::show_extra`, `Nav::select`: a `try_set` notifies even with the same value) and read through one memo, `Nav.shown` (the body, the pager's tabs, every tab's `lit`; `binding::view_tap`'s `deck` means any extra tab): a pager tap rebuilds no `PageView`, and a tap on the open deck tab does not mount `DeckView` again (its cleanup would lift the held keys). `DeckView` sends `deck_view` on mount and cleanup (the store sends it again after each hello while open; a hello leaves the deck info as it was, offline since the close, until the hub's `deck`: the tab never flickers and the open deck page stays mounted through a reconnect, and a hub restarted without `[companion]` with the same build keeps the tab until a reload), lifts every held key on `visibilitychange` hidden (`window_event_listener_untyped`: the event bubbles from the document to the window) and on cleanup (each up through `LiveStore::deck_press`; the cleanup's `lift_keys` leaves the outline's `held` alone, `.claude/rules/leptos-view-macro.md`), and forgets the holds when `connected` goes false (`Presses::clear`, no up: the hub's `Detach` releases them). Any pointer's down on the page first sends `Presses::missed_ups(ev.is_primary(), t)` (`lift_missed`, each an up through `deck_press`): a capture-phase `pointerdown` listener on the page's root (`NodeRef::on_load`, `add_event_listener_with_callback_and_bool(.., true)`; the closure and its element kept in a `StoredValue::new_local` and removed in the cleanup), so a finger on the rail or the grid's margin lifts a stale hold too, and a key's own down calls it again (finding none); a down in the column's head (`.column-head`: the tabs, the counter; `display: contents`) lifts nothing (`in_column_head`), as when the tabs sat outside the page (#63); a new grid shape (`columns`/`rows` changed) lifts every hold first (`leave_keys`, `tab`: a key gone from the grid takes the end of its touch with it). A key's down then goes when `behave::deck::can_press` holds (`LiveStore::can_send()`, Companion online, and not `LiveStore::dropping_out()`: the dropout counter's `active`, so a down never waits in a stalled link), else it flashes; every press's `t` is its pointer event's own time (`dom::event_epoch`; the tab's and the hidden page's ups `dom::epoch_now`), so the hub can refuse a down that waited (`late`, over 500 ms on the way); the outline's `held` is written only on a change (every key reads it). A press is sent at once or not at all (`LiveStore::deck_press` returns the failure handler when the socket refuses it; a refused down calls `Presses::unsent` at once, so its up never goes): never through the intent store, never resent (#43 L1 is deliberately not followed: a light must not switch late). Keys are `<button class="deck-key" use:owns_touches=…>` with Pointer Events only; a dispatched `pointerdown`'s `set_pointer_capture` result is ignored (no console line). Only a viewer gets `deck_keys`; each key reads its `Memo` of the map (a change redraws one key), its pressed flag and colour in place (`look.with`), cloning only the image's data URL. ## Mutation-proof by design (cargo-mutants 27 mutates every comparison, `!`, arithmetic, match guard, and constants in const expressions)

- A threshold is a one-line helper (`is_emergency`, `short_of_step`, `near_centre`, `within_epsilon`) tested at the exact float boundary and the next float (`0.03` vs `0.030000000000000002`), so `<`/`<=` cannot survive.
- **A recorder test's first `upload` takes every event that fits a batch (#43 PR D):** push the events a check is about AFTER that first upload, unless they cannot fit beside the lead event (walk `batch_count`: 100 + 972 bytes leave the 972 behind), or the first batch swallows them (the comma test of c951403 pushed 100 + 500 + 471 bytes first, its first batch took 100 + 500, and its full-batch case never ran: CI red, and the RED had failed for that reason, not the missing commas). Nothing compiles locally, so walk `batch_count` by hand for each upload in a new test.
- Prefer forms without equivalent mutants: `clamp`, `min`/`max`, `total_cmp`, `is_sign_positive`, `copysign` instead of hand-written comparisons that give the same result at the boundary.
- A constant built in a const expression (`FRAME_MS = 1000.0 / 60.0`) needs a test with a literal value (50 ms), not one that uses the constant on both sides.
- A window closed by a running sum of float steps (`diag/perf.rs`, 10 s of frame gaps): test with whole-ms gaps that reach the boundary exactly (625 × 16.0, 599 × 16.0 + 416.0 = 10 000), never 1000/60-ms steps whose float sum lands a hair under it and spills the next window's frames into this one; the boundary itself is tested on `window_full` with `10_000.0_f64.next_down()`.
- Fader-shaping traces come from the original `fader_script.lua` 2.5.4 run under Lua 5.4 (lupa; `math.pow = function(a, b) return a ^ b end`). Pick start levels far from 0 dB: near 0 dB, `a - b` and `a + b` of dB levels agree and a mutant survives (#8: the forcing check at start 0.7294 ≈ 0 dB).
