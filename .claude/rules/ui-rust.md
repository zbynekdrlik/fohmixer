# fohmixer-ui: where logic lives, and how it stays mutation-proof (#8)

## Pure decisions, thin browser glue

- Every decision is a pure, natively tested function or state machine: `behave/*` (TouchOSC behaviour and the redesign's scale, dB readout, colour, peak, SOLO ✕), `binding` (what is subscribed, the page selection), `arrange` (where the controls go, #63: lines, halves, the pager's region and its pins, the window and its arrows), `flow` (a control's kind, the instance a group names), `net` (handshake — a protocol the hub no longer serves or, since #26, a hub of another build reloads the page, once a minute at most —, reconnect schedule, HTTP answers), `diag` (#26: the diagnostic report's fields, the throttle — one report per kind per 5 s, a change within the window sent once when it ends with the state of then, an error message once —, `connected` vs `reconnect`; which close is a lost connection is `Conn::closed`), `diag/perf.rs` (#5 K4: the `perf` report — 10 s windows of the loop's frames give `fps` and `long_frame_ms`, a visibility change pauses the count and drops the gap after it, a periodic report at most once a minute as windows close, the pointers down at once with a primary pointer forgetting its type's missed ups, a report of its own for two or more at once, more than ever), `store.rs` (`Slot`, `Readiness`, `Wanted`, `next_range`, …), `store/conn.rs` (`Conn`: the connection's state machine — hello, reconnect, watchdog tick and its pings every 100 ms while visible, once a second while hidden, layout and instance changes), `store/intent.rs` (#43: the controls' writes as `set`s with the page's sequence, open until an ack at least as new; it also owns each key's failure handler — generic `F`, a plain value in tests — handed back on a failed ack; PR B: the states `sending` / `unconfirmed` (a release 1000 ms old without its ack) / `not_sent` (at a resend, a release 2000 ms old or older) / `confirmed` (nothing open), the release time from a final set or `release`, `touch` dropping a `not_sent` intent with its handler and holding one still on its way again, `live_value` closing a `not_sent` intent Live's fresh value equals (`same_number`: 1e-6, relative above 1), and `resend(instance, now)`: an instance back (`conn::back_online`: after each hello, or online again) gets its open intents as new `set`s with the page's next seq and the send time as `t`, a held control's always, a release only while younger than 2000 ms; an unsent write is kept, never a failure), `behave/link.rs` (#43: `DropoutWatch`, a dropout = ≥ 300 ms with nothing from the hub while a pong is due, or a lost socket; one count per interval; a silence counts only while the watch's own page tick keeps coming — a frozen or hidden page's late tick starts it over; finished dropouts go into the flight recorder; PR C: `counter()` = the dropouts since the last tap and `active`, `reset(now)` = 0 from here and the `reset` event — a dropout lasting through a tap stays red at 0) and `diag/trace.rs` (#43 PR C, reworked in PR D after the service of 2026-10-04 left it 30 minutes behind: the flight recorder `Recorder`, the event builders `touch`/`seq_of`/`intent` (PR E: a write's turn to `unconfirmed` at its release + 1 s or `not_sent` at the resend that kept it, from `store/intent.rs` `Intents::changes` on the link's tick, right after a resend and before an ack, a set or a touch closes or resets a write: `LiveStore::note_intents`)/`sock` (PR E dropped `send` and `ack`: the hub's `set` and `ack` records hold them, a frame's `mv` names its set); `moves.rs`: a fader's or pan's `touch_start` (`dt`, `c`, `travel`, `pos`, `live`, `local`, `from`) and `Trail` (a finger's pointer moves between frames, one `mv` per frame that sends: `e` `[dt, c]`, `r` the 1:1 finger position, `s` the position sent, `q` its set's seq; a touch's first `FIRST_MOVES` = 8 essential; numbers rounded); `rtt.rs`: one `rtt` summary a second of the pongs (`n`, `min`, `med` upper middle, `max`), no event per pong or ping; long frames over 50 ms but not the gap after a visibility change; `upload(now, ready, buffered, proof)` from the link's tick: a batch of at most 1 000 bytes, the `trace` envelope (`ENVELOPE`, 28 bytes) included, only when no set went since the previous tick (`set_went`, from `LiveStore::sent_set`), the socket holds at most 1 KB unsent (`takes_batch`: a ping still leaving never holds it — WebKit's `bufferedAmount` read above 0 at every tick for minutes, the PR C gate on 0 starved), the 10 KB/s cap (each batch waits its own bytes at that rate, `paced_until`: a full batch 97.7 ms, inside the 100 ms tick — counting the envelope outside the bound made it 103 ms, every second tick, half the rate; exactly 100 ms left no margin for a coarse clock) and it is due (a full batch — events that fill a message with their commas and the envelope — at once, less every 2 s, `soon()` after a hello, a dropout, a reset); past 768 KB unsent (PR E: no batch goes during a drag, so a 30 s drag of two faders at 60 Hz, ~610 KB, waits whole and drains at the cap once the fingers rest, ~75 s; PR D's 48 KB lost every drag over ~4 s) events go by `drop_rank`, oldest first within a rank: rank 0 (`rtt`, `frame`, any other kind), then rank 1 (`mv`); never the essential (`is_essential`: touch, dropout, reset, sock, visibility, overflow, intent, PR G's sys, zoom, #52's deck and #71's detail; `push_essential` for a touch's first 8 moves); the next batch carries one `overflow` per kind dropped (`Dropped`: `n`, `kinds`, `from`/`to` = the page time of the oldest and newest it dropped, min/max so a requeued older event widens it); the 20 000-event / 2 MB ring stays the last guard; `proved(n)`: a pong of a ping sent after a batch (`Conn::next_ping`, the hub reads a socket in order) proves it logged; `requeue()` on a lost socket sends the unproved batches again first, counted in the backlog again). A ping carries the latest pong's round trip and the number of the ping it measured (`rtt`, `rtt_n`; `Conn::ping`), reset on a new socket. The dropout watch ticks on its own 100 ms page timer (`LiveStore::tick_link`, `store/live/link.rs`), never on a socket's watchdog, so a socket lost during a page stall still counts from the next on-time tick; that tick also sets the counter's signal (`LiveStore::dropouts`, only on a change) and is the only place a recorder batch goes from (`upload`), so the writes and subscriptions a hello or an instance back sets off are on the socket first. Pure as well: `behave/hold.rs` (#71: the press on a strip's ☰, below), `behave/deck.rs` (#52: a Stream Deck key's `Presses`: down at the first finger, up at the last lift with the page's hold and why — `up`/`cancel`/`lost`/`hidden`/`tab` —, a down that cannot go flashes and its up never goes, `leave_all` for the tab and a hidden page, `clear` on a closed socket, `missed_ups`: a primary pointer's down — the browser's `isPrimary`, no other pointer down — first ups every hold still recorded, `lost`, so an end the browser never delivered leaves no key stuck in Companion, as `diag/perf.rs` forgets a missed up; a second finger's down releases nothing), `store/deck.rs` (#52: `key_side`, the square key in the measured area; `DeckWaiting`, the downs waiting for their `deck_ack`, the page's own press numbers) and `pages/deck.rs` `half_keys` / `half_vars` (#52, #63: each half's keys around the column, its columns, the rows and the key side from the left `.deck-area`'s measured size).
- The glue carries decisions out and decides nothing: `store/live.rs` (socket, timers, signals), `dom.rs`, `raf.rs`, the components, `diag.rs`'s browser half (listeners, the keepalive POST to `/api/client-report`; the store calls `diag::connected` on a hello and `diag::disconnected` when a socket that said hello closes; `raf::tick` hands `diag::frame` every frame's gap (the glue stamps it with `dom::now`, the clock the reports and the throttle use — a rAF time is the frame's start and can lie before the last report's stamp), and capture-phase pointer listeners on the window count every pointer — a new measure of the page reads the one frame loop, never a second `requestAnimationFrame` loop that would keep drawing on a page with nothing moving). The glue is excluded from mutation in `.cargo/mutants.toml` one function at a time, with a reason. New logic that lands in glue is a finding: extract it into a pure function and test it (the #8 review found three bugs hiding in the old untested `LiveStore`; the #26 review moved "which close is news" into `Conn::closed`).
- **A tablet's behaviour is a diagnostic report, not a console line (#26):** a new browser event worth knowing is a new `diag::Kind` reported through `diag`; the hub log and `/api/status` `client_reports` are where a deploy check reads what a tablet does. A report's `fetch` is awaited so a failed one is no unhandled rejection (the console guard), and the hub answers 204 even over its budget.
- **A lost hub connection keeps the values (#43, L2):** `on_close` turns each wanted slot with a value into `Slot::Stale` (`into_stale`); a stale slot is ready (the control is enabled and takes touches) and shows its value, the next value from the hub makes it fresh. I8's `Pending` stays for the first load, an instance reported offline and a key subscribed again while the hub is connected; a page switch goes through `Slot::rewanted(connected)` for the keys it adds and removes: `Pending` while the hub is connected, a known value kept stale during an outage (a page left and re-entered in the same outage still takes touches); each hello turns every slot no page wants `Pending` (`LiveStore::forget_unwanted`, `Conn::wants`), so a page left during one outage never comes back with that outage's value, and `LiveStore::apply` drops a value for a key no page wants (a `values`/`subbed` the hub sent before it read the unsub, late on a slow link: nothing would keep that slot current). A meter reads `Slot::fresh_number` (it falls, never freezes at a stale level) and the status light `Slot::is_fresh`.
- **A fader shows its open write (#43, L3, §4.3):** the frame loop asks `LiveStore::intent_view` for the first target's key (its state and open value) and tells `FaderCtl::intent(open, now)` and `write_at(law.pos(value))` before `frame`: while open the fader is local and, when no finger or glide drives it, sits at the write (a fader rebuilt by a page switch shows the write, not 0, and a touch starts from the cap); the close starts the post-release hold again. It writes `data-intent` (`confirmed`/`sending`/`unconfirmed`/`not_sent`) and, while the state `shows_ghost`, Live's position as `--g` with `data-ghost` (Live's value): the stylesheet `intent.css` (linked last) outlines the cap `--warn` / `--danger` and shows `.fader-ghost`, no text. The pan and the toggles (mute, solo, stage, param toggles) keep showing Live's value and get the outline only (#43 PR C): the pan's frame loop writes its key's `data-intent` (`LiveStore::intent_state`), a toggle registers `components::intent_look` (a frame function writing the `most_urgent` state of its keys, only on a change). A pointer's end goes through `behave::touch_end(drives, unsent)`: the unsent move as a final set, else `LiveStore::release` (the release time, L4); a glide's end (`FaderCtl::take_ended`) is a release too; a taken touch calls `LiveStore::touch`; a fader or pan taken away under a finger (`on_cleanup`) calls `release`. The pan records its release and touch the same way (`PanCtl::drives`, `LiveStore::touch` on its pointer down); toggles keep showing Live's value (P2), write final sets, and a tap inverts what the toggle shows (a write still on its way is not drawn on a toggle, so it is not what a tap inverts; round-2 review of #43). The write glue lives in `store/live/writes.rs` (`on_ack`, `resend`, `set`, `release`, `touch`, `intent_view`, `live_value`, the latter from `apply` through `store::write_key`).
- **A touch's first pointer move only anchors the drag (#43 PR F):** `FaderCtl::moved` / `PanCtl::moved` take the touch's first move (`first_move`, set at `press`) as the new `last_y` / `last_x` and move nothing (the iPad's first event comes ~83 ms late and 6–15 px away). `FaderCtl::anchoring(false)` keeps TouchOSC's first move: `FaderView` takes it from `Law::anchors` (the imported multi-target parameter faders, `Law::Linear`, do not anchor: the owner's call). A native test that drags a ctl writes that first move itself (`anchor(&mut f, id, <down's y>, t)` in `behave/fader/tests.rs` and `behave/pan.rs`; a move at the down's own coordinate moves nothing on the old or new code), else its first move is swallowed. The tap check still counts the anchor's slide (`FaderCtl::slip`, cut at the ends when it came: `clamp(pos + delta) − pos`; `tap_pos` = position + slip within 0..1, for every move and the release): without it a quick nudge whose one event slid the finger was a tap, and two of them glided the fader to 0 dB (PR F review, round 1); uncut, a slide past an end that the next moves came back from was a tap again (round 2). `touch_start_tests.rs` pins each path apart (a late lift, a slide and back lifted at once or still, a nudge before a double tap, a slide past each end). The shaping's emergency / calm sizes are fractions of `REFERENCE_TRAVEL` = 355 px (TouchOSC's strip on the FOH iPad), not of the fader's travel: `finger_size` (ratio first, so 355 px is exactly the old behaviour) and `Shaper::set_travel` from `press`. The page reads `clientY` as whole px (web-sys `client_y()` is `i32`): on a 207 px fader 1 px is about 0.1 dB or more (0.12 dB at 0 dB, more lower down, 0.0995 dB only at the very top), so the forced first step needs TouchOSC's travel in a test. The touch's first `mv` carries `a` (`Trail::moved(pointer, at, c, pos)` with the ctl's `pos()` right after the move).
- **The flight recorder hears the page (#43 PR C, PR D):** every control's touch (`components::trace_touch`: up / cancel when `TouchEnd::ends_touch`; a toggle's `tap` (mute, solo, stage: no up follows), a param toggle's down and its up by `touch_end_name`, never the `lostpointercapture` after it); a fader's or pan's taken down with where it started (`FaderCtl::press` / `PanCtl::press` give `behave::Start`, `components::trace_start` with `Press { at: dom::event_epoch(&ev), c, travel }`), its moves (the component's `Trail`: `moved` with each pointer move's own time and coordinate when the ctl took it, `components::trace_move` after each send from the finger with the first target's `seq`, `LiveStore::set` returning it; `end` at the touch's end); a write's turn to `unconfirmed` or `not_sent` (`store/live/writes.rs` `note_intents`, PR E; a write the socket took calls `Recorder::set_went`; since PR E neither a send nor an ack is an event), each pong into the round-trip summary (`store/live.rs`), the socket transitions, and `diag::frame` / the visibility listener (`diag.rs`) go into `diag::record` (`record_essential` for a touch's first moves). The recorder is one per page (a thread-local in `diag.rs`, `with_trace` for the store's uploads).
- **The controls own their touches (#43 PR G):** every tap target's root carries the directive `use:owns_touches=keys` (`components::owns_touches`: `dom::prevent_on` with `sys::CONTROL_PREVENTS`, `touchstart`, and its write keys in `data-keys`, `sys::KEYS_ATTR`, JSON); the surface's root `use:owns_surface` prevents `sys::SURFACE_PREVENTS` (`contextmenu`, `selectstart`, `dragstart`); `.surface *` is not selectable, called out or draggable (`style.css`). Only an active `touchstart` listener stops WebKit's loupe of a tap followed by a hold (bug 231161); `dom::prevent_on` adds ONE shared closure (a thread-local, no closure per element; a directive run again adds nothing) with `passive: false` on the element itself, never a Leptos `on:touchstart` (delegated to the window, where Chromium makes a `touchstart` listener passive by default and `preventDefault` there is ignored with a console intervention). A new tap target gets the directive (pass `Vec::new()` bound to a name when it writes no key: no turbofish in a `view!` attribute; `scripts/check_integrity.py` fails any element of a component or page, login.rs aside, whose start tag has `on:pointerdown` without `use:owns_touches`); a new control never uses `click`, which a prevented `touchstart` suppresses, and the gate fails any `on:click` (or other mouse event: `dblclick`, `mousedown` … `mouseleave`, all of which a prevented `touchstart` swallows) in a component or page (the login keypad and the shell's Try Again are not surface controls and keep it). The page's own background (a line's half, the column) keeps its touches: never prevent `touchstart` above a control.
- **The Stream Deck tab (#52, `pages/deck.rs`, `store/live/deck.rs`):** the tab is `Nav.deck`, never stored (a reload opens the last mixer page), written only on a change (`Nav::show_deck`, `Nav::select`: a `try_set` notifies even with the same value) and read through one memo, `Nav.deck_shown` (the body, the pager's tabs, every tab's `lit`): a pager tap rebuilds no `PageView`, and a tap on the open deck tab does not mount `DeckView` again (its cleanup would lift the held keys). `DeckView` sends `deck_view` on mount and cleanup (the store sends it again after each hello while open; a hello leaves the deck info as it was, offline since the close, until the hub's `deck`: the tab never flickers and the open deck page stays mounted through a reconnect, and a hub restarted without `[companion]` with the same build keeps the tab until a reload), lifts every held key on `visibilitychange` hidden (`window_event_listener_untyped`: the event bubbles from the document to the window) and on cleanup (each up through `LiveStore::deck_press`; the cleanup's `lift_keys` leaves the outline's `held` alone, `.claude/rules/leptos-view-macro.md`), and forgets the holds when `connected` goes false (`Presses::clear`, no up: the hub's `Detach` releases them). Any pointer's down on the page first sends `Presses::missed_ups(ev.is_primary(), t)` (`lift_missed`, each an up through `deck_press`): a capture-phase `pointerdown` listener on the page's root (`NodeRef::on_load`, `add_event_listener_with_callback_and_bool(.., true)`; the closure and its element kept in a `StoredValue::new_local` and removed in the cleanup), so a finger on the rail or the grid's margin lifts a stale hold too, and a key's own down calls it again (finding none); a down in the column's head (`.column-head`: the tabs, the counter; `display: contents`) lifts nothing (`in_column_head`), as when the tabs sat outside the page (#63); a new grid shape (`columns`/`rows` changed) lifts every hold first (`leave_keys`, `tab`: a key gone from the grid takes the end of its touch with it). A key's down then goes when `behave::deck::can_press` holds (`LiveStore::can_send()`, Companion online, and not `LiveStore::dropping_out()`: the dropout counter's `active`, so a down never waits in a stalled link), else it flashes; every press's `t` is its pointer event's own time (`dom::event_epoch`; the tab's and the hidden page's ups `dom::epoch_now`), so the hub can refuse a down that waited (`late`, over 500 ms on the way); the outline's `held` is written only on a change (every key reads it). A press is sent at once or not at all (`LiveStore::deck_press` returns the failure handler when the socket refuses it; a refused down calls `Presses::unsent` at once, so its up never goes): never through the intent store, never resent (#43 L1 is deliberately not followed: a light must not switch late). Keys are `<button class="deck-key" use:owns_touches=…>` with Pointer Events only; a dispatched `pointerdown`'s `set_pointer_capture` result is ignored (no console line). Only a viewer gets `deck_keys`; each key reads its `Memo` of the map (a change redraws one key), its pressed flag and colour in place (`look.with`), cloning only the image's data URL. The keys are two halves around the column; the key size is `half_vars` (`store::deck::key_side`) over the left `.deck-area`'s measured size, the same in both halves (deck.css's gap and padding equal `KEY_GAP`, `AREA_PAD`).
- **The system's gestures go to the recorder (#43 PR G, `diag/trace/sys.rs`):** `diag::listen_gestures` adds bubble-phase window listeners for `sys::RECORDED` and the visual viewport's `resize`. They run after the surface's and the controls' own listeners, which are on elements (`dom::prevent_on`), so `defaultPrevented` is final there; a Leptos `on:` handler for one of those events would be delegated to the window and registered after `diag::install`, so it would run after the recorder: prevent through `dom::prevent_on`, never an `on:` handler. `gesture` records `sys::sys` (`what`, `on` = `sys::kind`: the control root's `data-testid`, else the nearest one, else the tag, else `none` without an element; `keys` from `data-keys`, `pointer`, `prevented`) unless `sys::records(what, held)` leaves it out: a `lostpointercapture` only while its pointer is still down, `held` = `Perf::is_down` (the capture-phase `pointerup` / `pointercancel` listeners release it first, so the lift's own lost capture and a cancel's are left out; one lost while the finger is down is the system taking the touch, or the control going away under it, `on` none). `zoomed` records `sys::zoom` when `ZoomWatch::zoom` (two decimals, 1 at load) says the scale changed. Both kinds are essential (`drop_rank`).
- **The stylesheets (split from one file of 1161 lines, #43 PR C),** linked in cascade order by `index.html` and watched by `Trunk.toml`: `style.css` (fonts, tokens, login, surface, the tabs, the status with the dropout counter; #58 removed the Conf page), `page.css` (#63: the page's sides and the control column), `buttons.css`, `strip.css`, `detail.css` (#71: the channel detail, its pan and a strip's ☰), `states.css`, `intent.css`, `deck.css` (#52: the Stream Deck tab and its keys; #63 removed `phone.css`), `eq.css` (#71 PR E: the Pro-Q 4 cards and screen, linked after `detail.css`). Keep each under ~600 lines; a new component's rules go to its file, a new state to `states.css`.
- **A control writes through `LiveStore::set` (#43), never `cmd`:** `is_final` is true for a release (pointer up / cancel; a fader or pan sends one only when the touch's last move was still unsent — otherwise the frames already sent it and Live holds it), a toggle or a tap; a fader's or pan's per-frame sends are not final. The page clock a `set` and a `ping` carry is `dom::epoch_now()` (`performance.timeOrigin + performance.now()`), not `dom::now()`.
- Every bound control: its subscriptions come from the `binding` functions `control_subs` uses (`strip_subs` with the track colour, a strip on the page `StripSubs::shown`, every part but the pan, #71; `solo_sub`, `mute_sub`, `param_subs`; the channel detail `detail_subs`), its slot from `components::slot_of` (an unparseable path is a `Slot::Error`), `data-binding` + `aria-disabled` from one `Memo` of `Readiness` (red when unresolved, I5), and its event handler gates on the untracked readiness (`readiness_now`), not only on its own value.
- Moving parts register with `raf::animate(root, |el| Box::new(|now, step| …))`; handlers that capture a pointer also handle `on:lostpointercapture` (ends the touch like a cancel).
- **A text never overflows its box (#9), and nothing measures text (#21):** the strip's texts are sized in CSS from the strip width (`--strip-w`) and, for the name, its length `--n` (`behave::label::label_chars`, written once on the label: at most strip-w × 0.2, and `--n` capitals at 0.5 em + 0.5 px spacing within strip-w − 18 px); the instance tag's `clamp(7px, (strip-w − 22px) / 7, 8.5px)` fits "MASTER · RET" at every width. A rail button's text is `components::BtnText`: `--n` = its longest word (`longest_word_chars`), and `.rail .btn-text` fits that word in the button's 65 px text width (the rail's 1 px border counts: `box-sizing: border-box`), so a word never breaks ("TECHALER" / "T" on the real set). An ellipsis is the last guard. A new size formula is swept over every strip width 64–120 px in Chromium and WebKit before it ships (a render of the stylesheets with the strip markup, `scrollWidth` against `clientWidth`). Measuring text per element (the old `dom::fit_text`) forced a layout per text; after a width change and the fonts' arrival WebKit stopped drawing frames for a second (the CI iPad TechAlert blink). The E2E `clipped()` check keeps every text inside its box.
- **Style written from an effect stays off the reactive `style=`:** a reactive `style=move || …` rewrites the whole attribute and drops what `dom::set_style` wrote. The frame loop writes only elements whose `style` is not reactive (the fader, the pan, the meter's parts); the name button's colour is its reactive `style` (`--tc`, `--tt`), and nothing else writes it.
- **Where the controls go is `arrange.rs` (#63, the owner's design D15; it replaced the stylesheet's rows and `flow.rs`'s shared width of #21):** every page is its lines, each cut in two by one control column (`page.css`: `.body` a grid `1fr var(--col) 1fr`, `.column` in the middle spanning every line, each `.line` spanning all three columns under it). `PageModel::of(page)` numbers every group once (the rows' and every sub-page's) and keeps the rows' weights; `row_cells` makes a row's cells: each control one (a wide strip 1.1 units), a group of buttons or texts one `Block` (2.4 units, narrowed to a side at 64 px by `arrange`), an empty group nothing, and the pager one region of slots, as many as the largest sub-page's other controls plus every pinned control, each pinned control in the slot of its place in its sub-page on every sub-page (the next free one when taken; an exhaustive test of every pair of sub-pages of up to four strips finds no case that wraps), the shown sub-page's others in the free slots, `Blank` in the rest, every region cell one unit (a wide strip there is drawn normal, a block one strip wide: `CellView`), so nothing after the region moves on a sub-page switch. `lines`: each row a line while its weight's share of the height, less the 6 px gaps between lines, keeps 340 px, else one line of all rows. `split`: the cut where the wider half is the narrowest (the last such: an odd cell goes left). One gap (4 px) between any two cells, a group's or not (a wider gap between groups would make the region's width depend on the sub-page). The strip width: the widest at which every line's halves fit a side (`fit`), within 64–120 px, floored to 0.01 px on `.body`'s `--strip-w`; a line with a window counts 64 px, so a shift never resizes the strips. A line whose halves do not fit at 64 px (`shown`) drops its blanks and shows every pinned cell and a window over the others: the last window is as many of the last others as fit (so the last cell is always reachable), `offset` is clamped to its start, and the window from `offset` is as many as fit (`Shift`: `offset`, `free`, `step` ≥ 1, `last`, `total`; `moved` and `label`, `0/total` when no other cell fits beside the pins). `PageView` measures `.body` (client size less `BODY_PAD`) and the column (`offset_width`) on every resize, arranges with the selected sub-page and each line's offset (a `RwSignal<BTreeMap<LineKey, usize>>` the arrows write, kept by the line's key, `PageModel::line_key`: its rows and, where the pager is, the sub-page, so another sub-page, or a turned screen that joins or splits the rows into other lines, shows that line's window from its start and coming back finds it where it was; a turned screen with the same lines keeps each window, clamped by `shown`; the other lines keep theirs), and renders each line as ONE keyed list (`LineView`, `arrange::items`): a group's title (`Item::Title`, keyed by its group and how many titles of it come before in the line, `--n` cells and `--units` strips wide) before its run, then the run's cells (`Item::Cell`, keyed by `Cell::key`), each item's `data-side` read from the line's memo by its key (a `For` keeps the item it was made with); `page.css` orders them (`order`: the left side's, `.split` taking the rest of the left half and the column from the line's `--l-units`/`--l-cells`, the right side's, which so starts right after the column), and a title is a zero-width item whose line lies over its run (`margin-right: -4px` takes back its gap). ## Mutation-proof by design (cargo-mutants 27 mutates every comparison, `!`, arithmetic, match guard, and constants in const expressions)

- A threshold is a one-line helper (`is_emergency`, `short_of_step`, `near_centre`, `within_epsilon`) tested at the exact float boundary and the next float (`0.03` vs `0.030000000000000002`), so `<`/`<=` cannot survive.
- **A recorder test's first `upload` takes every event that fits a batch (#43 PR D):** push the events a check is about AFTER that first upload, unless they cannot fit beside the lead event (walk `batch_count`: 100 + 972 bytes leave the 972 behind), or the first batch swallows them (the comma test of c951403 pushed 100 + 500 + 471 bytes first, its first batch took 100 + 500, and its full-batch case never ran: CI red, and the RED had failed for that reason, not the missing commas). Nothing compiles locally, so walk `batch_count` by hand for each upload in a new test.
- Prefer forms without equivalent mutants: `clamp`, `min`/`max`, `total_cmp`, `is_sign_positive`, `copysign` instead of hand-written comparisons that give the same result at the boundary.
- A constant built in a const expression (`FRAME_MS = 1000.0 / 60.0`) needs a test with a literal value (50 ms), not one that uses the constant on both sides.
- A window closed by a running sum of float steps (`diag/perf.rs`, 10 s of frame gaps): test with whole-ms gaps that reach the boundary exactly (625 × 16.0, 599 × 16.0 + 416.0 = 10 000), never 1000/60-ms steps whose float sum lands a hair under it and spills the next window's frames into this one; the boundary itself is tested on `window_full` with `10_000.0_f64.next_down()`.
- Fader-shaping traces come from the original `fader_script.lua` 2.5.4 run under Lua 5.4 (lupa; `math.pow = function(a, b) return a ^ b end`). Pick start levels far from 0 dB: near 0 dB, `a - b` and `a + b` of dB levels agree and a mutant survives (#8: the forcing check at start 0.7294 ≈ 0 dB).

## web-sys 0.3.91 gaps

- `RequestInit` has no `set_keepalive`: set it on the init object with `js_sys::Reflect::set(&init, &"keepalive".into(), &true.into())` (`diag::post`). Check `~/.cargo/registry/src/*/web-sys-0.3.91/src/features/gen_<Type>.rs` for a setter before writing one, and add the `<Type>` feature to `crates/fohmixer-ui/Cargo.toml` (nothing compiles locally, so a missing feature costs a CI cycle).

## Trunk

WebKit warns ("preloaded using link preload but not used within a few seconds") about Trunk's default `<link rel="preload">` of the WASM, which fails every iPad test on the console guard. `Trunk.toml` sets `pattern_preload` to a `modulepreload` of the JS only; the `wasm` CI job checks the built `index.html` has no WASM preload.
