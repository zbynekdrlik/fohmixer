# S4 fohmixer-ui v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Ticket:** #8.

**Goal:** Build the engineer's touch surface in Leptos, reproducing the TouchOSC surface from the imported layout. It supports multi-touch faders, and every control shows Live's real state before it accepts input.

**Architecture:** See the design note `docs/superpowers/specs/2026-09-28-s4-ui-design.md` (section numbers are cited below).
- One scaled DOM stage, driven by the layout document.
- One shared `requestAnimationFrame` loop moves the fader caps and draws the meter canvases.
- Pointer Events with per-control pointer capture.
- A `LiveStore` context that talks the S3 client protocol.
- All behaviour logic sits in pure Rust modules, unit-tested natively.

**Tech Stack:**
- The S0/S3 workspace: Leptos 0.7 CSR, Trunk, web-sys (`PointerEvent`, `CanvasRenderingContext2d`), gloo.
- `fohmixer-proto` for the protocol and layout types.
- Playwright (Chromium, and WebKit iPad).

**Spec:** `docs/superpowers/specs/2026-09-28-fohmixer-program.md` §2.5, §3. Design: the note above. Behaviour source: `abl-touchosc` scripts (fader_script 2.5.4, mute_button 2.7.2, pan_control 1.5.3, meter_script 2.5.2, document_script 2.10.0). Their numbers are quoted in the design note, so the implementer does not need the scripts.

## Global Constraints

- **Tier 0:** no local cargo compilation. Only `cargo fmt`, `npx playwright test --list`, Python and ruff run locally. Batch the work and push once per CI cycle.
- **Versioning:** the first commit bumps the version to the next `-dev.N`.
- **Leptos disposal safety:**
  - `try_set` / `try_update` in every async or JS callback (`scripts/check_disposal_safety.py`);
  - no bare `<` / `>` inside `view!` attributes (`.claude/rules/leptos-view-macro.md`).
- **Every Playwright test uses the console-guard fixture**; zero console errors or warnings in both projects.
- **No `localStorage` access without try/catch.**
- **No per-event view re-render:** moving parts update through the rAF loop only.
- **Defaults** (from the parity inventory):

| Behaviour | Default |
|---|---|
| fader exponent | 0.515 |
| double-tap window | 50–250 ms |
| glide speed | 0.3 position/s |
| mute guard | 500 ms |
| pan double-tap | 300 ms |
| refresh debounce | 0.5 s |
| refresh flash | 300 ms |
| auto-refresh | 1 s after load |
| status pill | yellow < 150 ms, green by 500 ms |
| TechAlert blink | 300 ms |
| meter rise / fall | 300 / 200 ms |
| post-release snap | 1000 ms with shaping, 100 ms without |

## Review Focus

- **Two fingers on two faders:** each moves only its own fader, and releasing one does not stop the other. Tested in Task 4 in both projects.
- **A host restart mid-drag:** the dragged control keeps the finger's value, then snaps to Live's value after reconnect, with no stale value. Tested in Task 4.
- **A layout change while a page is open:** the subscriptions update and the old ones are released, with no leak of Live listeners (checked through the hub's `/api/status` subscription count). Tested in Task 2.
- **A token expired or revoked mid-session:** the WebSocket is closed with 401, the app returns to login, and there is no reload loop. Tested in Task 1.
- **A strip whose track is renamed in Live:** the strip turns red and its controls are disabled; after renaming the track back and pressing refresh, it binds again. Tested in Task 5.

### Task 3: Pure behaviour modules

**Files:**
- Create:
  - `crates/fohmixer-ui/src/behave/mod.rs`
  - `behave/fader.rs` (law, `Shaper`, taps, glide)
  - `behave/mute.rs` (guard)
  - `behave/pan.rs`
  - `behave/meter.rs` (ballistics, colour)
  - `behave/label.rs`
  - `behave/toggle.rs` (the `ParamToggle` aggregation and press modes)

**Interfaces:**
- Produces:
  - `fader::to_live(p) -> v`, `fader::to_pos(v) -> p`
  - `Shaper::new(enabled)`, `.start(p0, v0)`, `.move_to(p_raw, t_ms) -> p`
  - `TapDetector::on_up(moved, dt_ms, t_ms) -> Option<Tap>`
  - `Glide::new(from, to, t0).at(t) -> (p, done)`
  - `MuteGuard::on_tap(t_ms) -> GuardAction`
  - `pan::to_live(p)`, `pan::color(p)`
  - `MeterBallistics::step(target, dt_ms) -> level`, `meter::color(db) -> Rgb`
  - `label::strip_label(name) -> String`
  - `toggle::aggregate(&[bool]) -> ToggleState`, `toggle::on_press(mode, …) -> Vec<Write>`
- [ ] **Step 1: Write the failing unit tests** with exact values from the design note:
  - `to_live(0.5) ≈ 0.700` and `to_pos(0.85) ≈ 0.7294`;
  - `Shaper`: a first move of 0.002 is forced to a ±0.1 dB step; reaction compensation then scales the next three moves by 0.3, 0.5 and 0.7; a move above 0.03 passes through unscaled;
  - taps: 60 ms apart gives a double tap; 300 ms apart gives none;
  - glide: from 0 it reaches 0.7294 after about 2.43 s;
  - mute guard: a second tap at 400 ms applies, and one at 600 ms re-arms;
  - pan colour at 0.5 is grey and at 0.6 is cyan;
  - meter: after a 300 ms rise it is at the target; after 100 ms of fall it is halfway;
  - colour thresholds at −2, −10 and −20 dB;
  - labels: `"B-Main repro #"` gives `"Main"`, `"Vocal 1 repro#"` gives `"Vocal"`;
  - toggle aggregation: all on, all off, and mixed;
  - the press modes' write lists.
- [ ] **Step 2: Implement** each module. **Step 3: Commit** — `feat(ui): fader, mute, pan, meter, label and toggle behaviour (#8)`.
