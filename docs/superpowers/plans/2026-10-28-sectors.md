# Fader Sectors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The FOH page shows four fader sectors (`lu`, `ld`, `ru`, `rd`) around the control column, each paging through its own named layouts. The layouts live in a hub-owned `sectors.json`. A strip's SEL detail ticks which layouts it is in, ARRANGE reorders the strips, and ↶ undoes the last change.

**Architecture:**
- A pure model in `fohmixer_proto::sectors` covers the document, its checks, a fader's identity, the pool, units/FULL, the seed, and applying a tick or an ARRANGE save. The hub and the UI share it.
- The hub keeps the document in `SectorStore` (`sectors.rs`: load, poll, atomic write, `.prev`, undo). `router/sectors.rs` handles the three page messages, the attach push, the seed, the records and the status.
- On the UI side the pure parts are `arrange/sectors.rs` (lines, width, windows), `binding/sectors.rs` (the device's picks, the subscriptions, the detail's ticks, the pool steps) and `behave/arrange_drag.rs` (the reorder mode and its drag). The glue is `pages/sectors.rs` (the page, the LAYOUTS block, ARRANGE, ↶) and `components/detail_layouts.rs` (the detail's section).

**Tech Stack:** Rust 2024 (serde, tokio, axum in the hub; Leptos 0.7 in the UI), Playwright (TypeScript), Python 3.11 (the e2e harness).

**Spec:** `docs/superpowers/specs/2026-10-28-sectors-design.md` (binding). The approved look is `docs/mockups/sectors-v1.html` (commit `1d5e4d0`). The decisions are in #148's comments.

## Calls made in this plan (recorded on #148 with the plan commit)

1. **The pool also holds a `param_fader` that has a label** (the backing-tracks fader). Its identity is `StripRef { instance: <its link's instance, else its first target's binding instance>, label }` and it takes 1 unit. Without this, Podklady All would vanish from the FOH page. This deviates from spec §2, which says strips only.
2. **Frame strips without a label:** a `Track`/`Return` anchor uses its name and `Master` uses `"Master"`. `Song` has no identity.
3. **Only one save message, `SectorOrders { id, orders, rev }`.** A one-layout save is a one-item list. There is no separate `SectorOrder` message.
4. **Every sector request carries the page's `id`.** The hub answers `ServerMsg::Result { id, data: [] }` when it takes the request and `ServerMsg::Error { id: Some(id), message }` when it refuses one. The page's existing pending-request map (`LiveStore::finish`) routes both, so the checkbox flash and ARRANGE's exit know their answer.
5. **The refusal words:** `FULL`, `stale`, `unknown layout`, `not in the pool`, `nothing to undo`, `no layout served`.
6. **The undo flag:** `ServerMsg::Sectors { doc, undo }`, where `undo` is true while the hub holds `sectors.json.prev`. It drives ↶.
7. **Revisions.**
   - The hub owns `rev`. Every change it makes is `rev + 1`, written into the file.
   - A hand edit is served at `max(file.rev, served.rev + 1)` and is not written back.
   - A hand edit is a change: `prev` becomes the document before it.
   - The seed is `rev` 1 with no `prev`.
8. **A bad file.** At start the hub serves the empty document (sectors off). Later the last good document stays served. `/api/status` `sectors.error` says why. There are no backups.
9. **The seed waits for the markers.** It runs only when `sectors.json` is missing, the served layout's pool is not empty, and every configured instance has had one whole marker read since the hub started (`Keeper::has_read`, new) with no composition pending. The seed's end-to-end proof is a router unit test on the REVERB tests' `marked` router. The `it` tests start from a written file.
10. **Seed details.**
    - Rows past row 1 are ignored.
    - Titles are cut to 8 characters.
    - Layout ids are `<sector>-<n>` from 1.
    - A pager row's other groups become one right layout, titled with the first group's title, else `MAIN`.
    - A row without a pager is cut at a group boundary where `max(left, right)` strip count is smallest. On a tie the cut with more on the left wins.
    - The seed never enforces FULL.
11. **FULL** is enforced only on a tick. A hand-edited or seeded layout over 6 units is valid; the page narrows the strips or windows the sector. A ref no pool strip carries takes no room.
12. **Unknown fields:** every proto struct has `deny_unknown_fields`, and `sectors` is a map keyed by the `SectorId` enum, so an unknown key fails the parse. Each layout must have a non-empty id and title, and no strip may appear twice in one layout.
13. **A no-op tick** (on while already in, off while not in) is taken with no write, no record and no broadcast; it gets only its `result`.
14. **Phones.** A side whose need does not fit at 64 px gets a window per side, keyed by that side's sectors. The column shows that side's ◀ ▶. The thin strip's ◀ ▶ stay hidden on the sectors page; the phone design follows on #148.
15. **The detail's ◀ ▶** step through the pool's strips only (param faders are skipped), with no wrap. The recorder logs the open with `why: "step"`.
16. **The instance tag** on a sector strip follows `flow::shared_instance` over its shown layout's controls. The group's side name is never drawn on the sectors page.
17. **The sector file poll** rides the layout poll's tick: `poll_layout` also sends `RouterMsg::SectorsPoll`.
18. **The harness reset** writes the empty document. The hub's in-memory `prev` stays, so tests never rely on ↶ being dim at their start.

## Review Focus

2. **A strip renamed in Live, so its ref is no longer in the pool.** It stays in the document, shows nowhere, counts in `unknown`, and shows again when renamed back. The test is in Task 1 (`a_ref_no_pool_strip_carries_takes_no_room_and_counts_unknown`) and Task 5 (`an_unknown_ref_is_left_out_of_the_cells`).
3. **The picked layout id is gone after an edit.** The sector falls back to its first layout, and the stored pick is not overwritten until the user pages. The test is in Task 5 (`a_pick_whose_layout_is_gone_falls_back_to_the_first`).
4. **Two pages tick the same full layout at once.** The hub takes exactly one and refuses the other `FULL`. The test is in Task 4 (`two_ticks_into_the_last_unit_take_one_and_refuse_the_other`).
5. **A hub restart while a page is attached.** The page gets the document again at the reconnect. The stored picks survive, and an ARRANGE in progress ends unsaved. The tests are in Task 4 (`a_page_gets_the_document_at_attach`) and Task 8 (`a_new_document_during_arrange_ends_it_unsaved`: the reconnect's document goes through `doc_arrived`).

```rust
pub enum SectorId { Lu, Ld, Ru, Rd }
impl SectorId {

    pub fn up(self) -> bool;                 // Lu, Ru

#[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct StripRef { pub instance: String, pub label: String }

#[serde(deny_unknown_fields)] pub struct SectorLayout { pub id: String, pub title: String, pub strips: Vec<StripRef> }
#[serde(deny_unknown_fields)] pub struct SectorsDoc { pub rev: u64, pub sectors: BTreeMap<SectorId, Vec<SectorLayout>> }
#[serde(deny_unknown_fields)] pub struct SectorOrder { pub layout: String, pub strips: Vec<StripRef> }

impl SectorsDoc {
    pub fn empty() -> Self;                                   // rev 0, no sectors
    pub fn is_on(&self) -> bool;                              // at least one layout
    pub fn layouts(&self, sector: SectorId) -> &[SectorLayout];
    pub fn find(&self, id: &str) -> Option<(SectorId, &SectorLayout)>;
    pub fn validate(&self) -> Vec<String>;                    // empty: valid
    pub fn layout_count(&self) -> usize;
    pub fn strip_count(&self) -> usize;                       // distinct refs
}

pub struct Pooled<'a> { pub id: StripRef, pub control: &'a Control }
impl Pooled<'_> { pub fn units(&self) -> f64; pub fn strip(&self) -> Option<&Strip>; }

pub fn strip_ref(control: &Control) -> Option<StripRef>;
pub fn pool(layout: &Layout) -> Vec<Pooled<'_>>;
pub fn units(strips: &[StripRef], pool: &[Pooled]) -> f64;
pub fn is_full(units: f64) -> bool;                           // units > SECTOR_UNITS
pub fn would_be_full(layout: &SectorLayout, strip: &StripRef, pool: &[Pooled]) -> bool;
pub fn unknown(doc: &SectorsDoc, pool: &[Pooled]) -> usize;   // distinct refs not in pool

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Refusal { UnknownLayout, NotInPool, Full, Stale, NothingToUndo, NoLayout }
impl Refusal { pub fn text(self) -> &'static str; }  // "unknown layout","not in the pool","FULL","stale","nothing to undo","no layout served"

pub fn tick(doc: &SectorsDoc, layout: &str, strip: &StripRef, on: bool, pool: &[Pooled]) -> Result<Option<SectorsDoc>, Refusal>;
pub fn orders(doc: &SectorsDoc, orders: &[SectorOrder], rev: u64) -> Result<SectorsDoc, Refusal>;
pub fn seed(layout: &Layout) -> SectorsDoc;
```

Rules the tests pin:
- `strip_ref`:
  - A `Strip` in conflict (`mark == Some(StripMark::Conflict)`) or one with a placeholder label (`markers::has_placeholder_label`) has no ref.
  - Otherwise its `label` is used. With no label: a `Track`/`Return` anchor uses its name, `Master` uses `"Master"`, and `Song` has none.
  - A `ParamFader` uses its `label`, with the instance of its `link`, else its first target's binding (call 1). Every other control has no ref.
- `pool`: walk `Layout::controls()` (every page, the views and rails included, in document order) and keep each ref once, first wins.
- `tick`:
  - The layout id must exist, else `UnknownLayout`. On a tick that turns a strip on, the strip must be in the pool, else `NotInPool`.
  - On appends the strip at the end. It is refused `Full` when `would_be_full`.
  - Off removes the strip, whether or not the pool carries it.
  - A tick that changes nothing is `Ok(None)`. A change returns the doc with `rev + 1`.
- `orders`:
  - `rev` must equal `doc.rev`.
  - Each layout must exist and appear once in `orders`.
  - Each `strips` must be the same multiset as the layout's strips.
  - Anything else is `Stale`. On success the result has `rev + 1`.

**Interfaces (Produces):**

```rust
pub const SECTORS_FILE: &str = "sectors.json";
pub const PREV_FILE: &str = "sectors.json.prev";

#[derive(Debug, Clone, PartialEq)]
pub enum Polled { Taken, Refused(String) }

pub struct SectorStore { /* dir, doc, prev, missing, seen: Option<(SystemTime,u64)>, written: Option<Vec<u8>>, error */ }
impl SectorStore {
    pub fn open(data_dir: &Path) -> Self;
    pub fn doc(&self) -> &SectorsDoc;
    pub fn has_prev(&self) -> bool;
    pub fn missing(&self) -> bool;          // no sectors.json on disk
    pub fn error(&self) -> Option<&str>;
    pub fn poll(&mut self) -> Option<Polled>;
    pub fn commit(&mut self, next: SectorsDoc) -> std::io::Result<()>;   // prev := current; writes .prev then the file
    pub fn seed(&mut self, seeded: SectorsDoc) -> std::io::Result<()>;   // writes the file; prev none
    pub fn undo(&mut self) -> Result<std::io::Result<()>, Refusal>;      // NothingToUndo without prev; else swap, rev = current.rev + 1
}
pub fn parse(text: &[u8]) -> Result<SectorsDoc, String>;   // serde, then validate() joined with "; "
pub fn served_rev(file_rev: u64, served_rev: u64) -> u64;  // max(file_rev, served_rev + 1)
```

The writes go through `crate::atomic_write`; its temp names are `sectors.tmp` and `sectors.json.tmp`. After its own write the store records the file's metadata and bytes, so the next `poll` takes nothing. A poll that reads bytes equal to `written` takes nothing either: that is a rewrite in place, or the hub's own write.

How the arrangement is decided (`arrange_sectors`, the one algorithm not fixed by its signature):
- Each side of each line has a **need**: for each of its sectors, take the layout whose cells have the widest `span(.., m.min)` (ties: the first), and concatenate those cells.
- A side whose need fits at `m.min` gives the candidate width `(sides.width - (n-1)·gap) / units`. A side that does not fit is windowed and gives `m.min * stretch(sides)`. An empty side gives no candidate.
- `width = min(candidates).clamp(m.min, m.max)`. It depends on the document and the screen only, never on the picks, so paging resizes nothing.
- A side's shown cells are its picked layouts' cells, concatenated in the side's sector order. A windowed side shows a window from `offset(key)` over them: as many as fit at `m.min`, offset clamped so the last cell is reachable, the same as `arrange::shown`'s window without the pins.
