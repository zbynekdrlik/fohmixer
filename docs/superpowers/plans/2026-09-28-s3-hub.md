# S3 Hub + Proto + TouchOSC Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Ticket:** #7.

**Goal:** A thin Rust hub that connects to N FohMixer instances, fans their values out to many clients, serves the layout, runs the STAGE AUT rule and does the auth. Plus a one-shot Python tool that imports the TouchOSC project and the band set's MIDI mappings into `layout.json`.

**Architecture:** see the design note `docs/superpowers/specs/2026-09-28-s3-hub-design.md` (section numbers are cited below). The hub is a pass-through plus a subscription cache: it never builds a mixer model. It is tested against real `sim/host.py` processes running the real FohMixer script (S2).

**Tech Stack:**
- The S0 workspace: axum 0.8, tokio 1, tokio-tungstenite, serde.
- Auth copied from iemmixer: jsonwebtoken 9, argon2 0.5, DPAPI on Windows.
- The import tool: Python 3.11 standard library.

**Spec:** `docs/superpowers/specs/2026-09-28-fohmixer-program.md` §2.4–2.7, §3.2. Design: the note above. The K3 triage is on #5.

## Global Constraints

**Builds and versions**
- Tier 0: no local cargo compilation. Only `cargo fmt`, `cargo metadata`, `cargo generate-lockfile` and Python run locally. Everything else runs in CI; batch the work and push once per cycle.
- The first commit bumps the version to the next `-dev.N` (`Cargo.toml`, `Cargo.lock`, `live-script/FohMixer/version.py`).

**Repo hygiene.** The repo is public: the fixtures use only the synthetic site names from S2 (`sim/fixtures/test-site.json`).

**Hub behaviour**
- It never reinterprets LOM values; the one exception is the STAGE AUT rule (spec §2.4).
- Each client connection keeps only the latest value per subscription key while a send is pending. There are no unbounded queues.
- Defaults:
  - HTTP port 8480;
  - instances band 39101 and master 39102;
  - reconnect backoff 250 ms doubling to 2 s;
  - busy when `main_tick_age_ms` > 150 or there is no heartbeat for 300 ms;
  - 30 layout backups.

## Review Focus

- **A host restart while clients are subscribed:** each client gets offline, then online, then fresh values with no duplicate Live listeners. Tested in Task 3.
- **A name binding whose track was renamed during a session:** the subscriber gets `{"sub","error"}` and not a stale value. Tested in Task 3.
- **A client that stops reading:** other clients' pushes are delayed by less than 50 ms, and the hub memory stays bounded (coalescing). Tested in Task 3.
- **An invalid `layout.json` written in place:** the last good layout keeps being served, and `/api/status` reports the error. Tested in Task 4.
- **STAGE AUT with the flag on during a set reload:** the rule re-subscribes and applies once after reconnect, and never writes twice for one change. Tested in Task 5.

### Task 1: Protocol and layout types in `fohmixer-proto`

**Files:**
- Create: `crates/fohmixer-proto/src/client.rs` (design §3), `crates/fohmixer-proto/src/layout.rs` (design §5).
- Modify: `crates/fohmixer-proto/src/lib.rs` (the `mod` declarations and re-exports).

**Interfaces:**
- Produces:
  - `ClientMsg`, `serde(tag="type")`: `Cmd{id, instance, commands: Vec<LiveCommand>}`, `Sub{instance, target, prop, display: Option<bool>}`, `Unsub{sub}`, `SetHub{key, value}`.
  - `ServerMsg`: `Hello{proto, build, min_client_proto}`, `Result{id, data}`, `Subbed{sub, value, display}`, `Values{items}`, `Instance{name, online, busy, set_name}`, `Hub{key, value}`, `Layout{rev}`, `Error{id, message}`.
  - `LiveCommand{target: serde_json::Value, name: String, args: serde_json::Value}`.
  - `Layout{schema, canvas, pages, overlay, config, report}` and `Item` (an enum by `kind`), `Binding{instance, anchor: Anchor, path: Option<String>}`, and `Layout::validate(&self) -> Vec<LayoutError>`.
  - `pub fn hub_key(instance, target, prop, display) -> String`, which normalises the whitespace in `target`.
  - `pub const UI_PROTO: u32 = 1`.
- [ ] **Step 1: Write the failing tests.**
  - Serde round-trips for every message.
  - A sample layout JSON literal in the test parses.
  - `validate` flags, one case each:
    - a duplicate id;
    - a frame outside the canvas;
    - an unknown kind (a serde error);
    - a bad path, e.g. an unbalanced `[name=`;
    - a `param_toggle` with no targets.
  - `hub_key` collapses runs of spaces.
- [ ] **Step 2: Implement.** The path grammar check is a small parser equal to S2 §3.1: root word, then steps `attr`, `attr N` or `attr[name=…]` with `\]` and `\\` escapes.
- [ ] **Step 3: Commit** — `feat(proto): client protocol and layout document types (#7)`.

### Task 7: TouchOSC import tool

**Files:**
- Create:
  - `tools/import-tosc/import_tosc.py`
  - `tools/import-tosc/build_fixtures.py`, which writes `fixtures/test.tosc` (zlib XML) and `fixtures/test.als` (gzip XML) from Python literals using only synthetic names
  - `tools/import-tosc/test_import_tosc.py`

**Interfaces:**
- Consumes: the layout schema from Task 1 (it mirrors design §5 exactly).
- Produces: `layout.json` and `report.md`.
- [ ] **Step 1: Write the failing tests** on the fixtures:
  - pages, the nested pager and the root overlay are present;
  - frames are composed into canvas coordinates (a child at (10,10) in a group at (100,100) on a page at (0,59) gives (110,169));
  - strip kinds are recognised: standard, narrow, solid, meter_mute_only;
  - decorative script carriers are dropped (backdrop buttons with the mute script, the second meter bar);
  - `double_click_mute` becomes `mute_guard`;
  - `unfold` goes into `config`;
  - MIDI controls:
    - an on/off mapping with thresholds 64–127 becomes a `param_toggle` on the activator;
    - a full-range continuous mapping becomes a `param_fader` with `cc_linear`;
    - a rack-macro mapping becomes a path `devices[name=<rack>] parameters 1`;
    - an unmapped CC is dropped into `report`;
  - off-canvas and hidden nodes go into `report`;
  - the output validates against the Rust schema. A Rust test in `fohmixer-proto` parses `tools/import-tosc/fixtures/expected-layout.json`, a file the Python test writes and CI compares with `git diff --exit-code`.
- [ ] **Step 2: Implement** per spec §2.6 and design §7, using the K3 findings on #5 for the `KeyMidi` semantics (0-based channel, `MidiCCOnOffThresholds`, rack macro bus channel 16 ignored).
